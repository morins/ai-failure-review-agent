# ai-failure-review-agent — 실패 유형 기반 AI 검토 에이전트

> AI가 써 준 글 · 표 · 그림을 그대로 믿기 전에 **어디가 어떻게 틀릴 수 있는지**를 열 가지 유형으로 짚고, **무엇을 확인해야 하는지**를 표로 뽑아 주며, 그 확인 과정을 **다섯 단계 관문**으로 보여 주는 공개 프로젝트입니다. 코드를 몰라도 쓸 수 있고, 올린 파일은 어디로도 가지 않습니다.

[English README](README.md) · 라이선스 CC BY-NC 4.0(상업적 이용은 별도 협의) · ⓒ METACURATION · 실제 자료 없음(모든 예시는 가상) · 기본 모드 외부 서버 없음

## 이 프로젝트가 하는 일

1. **실패 유형 사례집** — AI 답변이 틀리는 모양을 열 가지로 나누고, 유형마다 증상 · 원리 · 확인 순서 · 예방 규칙을 적었습니다. 짧은 가상 사례 100건(C-001 ~ C-100)이 부록으로 붙어 있습니다. → [cases/](cases/)
2. **검토 체크리스트와 도구** — 답을 받았을 때, 일을 맡기기 전에, 끝난 뒤에 볼 체크리스트 6종. 그리고 AI 답변 파일에서 확인할 문장을 자동으로 뽑아 **검토표**를 만들고, 그 표가 규칙대로 적혔는지 검사하는 작은 도구 2개(파이썬, 설치 없음). → [checklists/](checklists/) · [tools/](tools/)
3. **검토 에이전트 페이지** — [failure-peer-review-agent.html](failure-peer-review-agent.html)을 브라우저에서 열어 파일을 끌어다 놓으면 "업로드 → 검토 → 실패 감지 → 보완 → 통과"의 다섯 단계와 열 가지 유형을 눈으로 볼 수 있고, 결과를 검토표(.md)와 JSON으로 내려받을 수 있습니다. 기본은 데모이고, **본인 API 키를 넣으면(선택) 텍스트 파일을 실제 AI 모델이 검토**합니다.

한 줄로 — **"AI가 다 됐다고 해도, 통과 판정은 사람이 한다"** 를 실제로 해 볼 수 있게 만든 도구 상자입니다.

## 30초 체험 — 데모 페이지 열기

1. 이 저장소를 내려받거나 복제합니다(초록색 **Code** 단추 → Download ZIP).
2. `failure-peer-review-agent.html`을 더블클릭해 브라우저에서 엽니다. 서버 · 설치 · 로그인이 필요 없습니다.
3. 아무 파일이나 끌어다 놓고 **검토 시작**을 누릅니다. 다섯 단계가 차례로 켜지고, 유형별 지적이 빨강으로, 보완 후보가 파랑으로 표시됩니다.
4. **검토표 내보내기(.md)** 를 누르면 판정 칸이 비어 있는 검토표가 내려받아집니다. 판정은 직접 적습니다.

솔직하게 적어 둡니다 — 기본 모드는 **시뮬레이션**입니다. 실제 AI 모델을 부르지 않고 파일 내용을 읽지도 않습니다(이름과 크기만 사용). 외부로 나가는 요청은 하나도 없습니다.

**실제 모델 연결(선택)** — 페이지의 "실제 모델 연결" 칸에 제공자(OpenAI 호환 · Anthropic) · 엔드포인트 · 모델 · 본인 API 키를 넣으면 .txt · .md · .csv · .json 파일(앞 60,000자)을 실제 모델이 읽고 "확인할 지점"을 열 가지 유형으로 돌려줍니다. 키와 파일 내용은 브라우저에서 **본인이 지정한 제공자에게만** 전송되고, 이 페이지에는 서버가 없어 저장소 운영자에게는 아무것도 오지 않습니다. 개인정보 · 기관 내부 자료는 넣지 마세요. 모델이 돌려준 것도 판정이 아니라 확인할 지점의 목록입니다 — 통과 · 미통과는 사람이 적습니다.

## 3분 실전 — 검토표 만들기

파이썬 3만 있으면 됩니다(설치할 것 없음).

1. 검토할 AI 답변을 `.md` 또는 `.txt` 파일로 둡니다. 연습용으로 `raw/`에 일부러 오류를 심은 가상 예시 두 건이 있습니다.
2. 검토표를 만듭니다. 수치 · 출처 · 주소 · 시점 · 단정 문장을 뽑아 7열 표로 만들어 줍니다.

```bash
python tools/make_review_sheet.py raw/예시_AI답변_02_통계요약.md
```

3. 생성된 `out/검토표_예시02_통계요약.md`를 열어 **판정**(통과 · 미통과 · 〔확인 못 함〕)과 **근거**를 적습니다. 도구는 판정하지 않습니다.
4. 규칙대로 적었는지 검사합니다. 통과 · 미통과인데 근거가 비어 있으면 멈춥니다.

```bash
python tools/check_review_sheet.py raw/예시_AI답변_02_통계요약.md out/검토표_예시02_통계요약.md
```

완성된 모양은 [out/검토표_예시01_정책브리프.md](out/검토표_예시01_정책브리프.md)에 있습니다(사람이 판정을 적은 상태).

## 다섯 가지 원칙

1. **매끄러움은 증거가 아닙니다.** 모델은 저장된 사실을 찾아 쓰는 것이 아니라 확률적으로 이어질 말을 고릅니다. 그래서 틀려도 유창합니다.
2. **"확실해?"는 소용없습니다.** 같은 추측을 한 번 더 시키는 것뿐입니다. 대신 대조할 원문, 근거로 삼을 범위, 결과를 적을 파일을 줍니다.
3. **검증과 확인은 다릅니다.** 검증은 요구대로 만들었는가(기계에 맡길 수 있음), 확인은 받는 사람의 필요를 채우는가(사람의 일). 하나를 통과해도 다른 하나는 남습니다.
4. **맡기기 전에 저장점을 만들고, 끝나면 바뀐 줄을 읽습니다.** 에이전트가 내 파일을 직접 고치므로 무엇이 · 언제 · 왜 바뀌었는지 남기는 장치가 필요하고, 받아들일지 되돌릴지는 사람이 정합니다.
5. **확인하지 못한 것은 확인했다고 적지 않습니다.** 〔확인 못 함〕은 실패가 아니라 정직한 기록입니다. 산출물의 책임은 검토하고 내보낸 사람에게 있습니다.

## 자주 묻는 질문

- **진짜 AI가 들어 있나요?** 기본 모드에는 없습니다. 페이지는 절차를 보여 주는 시뮬레이션이고, 도구는 정규식으로 확인할 문장을 뽑을 뿐입니다. 본인 API 키를 넣으면(선택) 실제 모델이 텍스트 파일을 검토하지만, 그 결과도 "확인할 지점"이지 판정이 아닙니다. 판정은 사람이 합니다.
- **올린 파일은 어디로 가나요?** 기본 모드에서는 어디로도 가지 않습니다 — 외부 요청이 없고(스크립트 · 폰트 · 분석 도구 모두 없음) 파일 내용을 읽지 않습니다. 실제 모델 모드에서는 본인이 지정한 API 제공자에게만 갑니다. 도구는 내 컴퓨터에서만 돌고 결과를 `out/`에 씁니다.
- **사례는 실제 사건인가요?** 아니요. 100건 모두 실제 인물 · 기관 · 고객과 무관한 가상 예시이고, 연습용 답변 두 건도 첫 줄에 가상임을 적어 두었습니다. 특정 제품을 겨냥하지 않습니다.
- **왜 통과 · 미통과를 자동으로 매겨 주지 않나요?** 만든 쪽이 스스로 채점하면 "됐다"로 기우는 것이 이 저장소가 다루는 실패 유형 가운데 하나(06)이기 때문입니다. 도구는 무엇을 확인할지 뽑고 모양을 검사하는 데까지만 합니다.
- **수업 · 연구 · 회사에서 써도 되나요?** 학습 · 교육 · 연구 · 개인 이용은 출처(ⓒ METACURATION · 저장소 주소)만 적으면 자유롭게 쓰고 고치고 나눌 수 있습니다(CC BY-NC 4.0). **영리 목적 이용(기업 교육 · 유료 강의 · 유료 서비스 · 제품 포함)은 별도 협의** — 저장소 이슈로 문의해 주세요.
- **내 상황에 맞게 바꾸려면?** 체크리스트와 양식은 복사해서 고쳐 쓰고, 새 사례는 [CONTRIBUTING.md](CONTRIBUTING.md)의 양식으로 보태 주세요.
