# 00 · GitHub 공개 가능 · 불가 기준

> 원칙 — **공개 자료를 근거로 내가 새로 쓴 것은 공개 가능, 남의 원문 · 비밀값 · 개인정보 · 내부 자료 · 유료 자산은 불가.** 올라간 것은 회수가 어렵다. 그래서 점검은 첫 커밋 전에 한다.

## 1 공개 가능

## 2 공개 불가

| 항목 | 이유 | 막는 장치 |
|---|---|---|
| 타인의 저작물 원문(강의 자료 · 교재 · 유료 자료 · 논문 전문) | 저작권 · 배포권 | 요약하고 출처만 · 원문 PDF는 .gitignore(*.pdf) |
| 개인정보(실명 · 연락처 · 주민번호 · 계좌 · 학번) | 노출 · 법적 책임 | 커밋 전 검색(이메일 · 전화 · 주민번호 패턴 · 실명) · 제출자 정보는 LMS 제출란에 |
| 비밀값(비밀번호 · API 키 · 토큰 · .env · 인증서) | 보안 사고 · 이력에 영구히 남음 | .gitignore(.env · *.key · *.pem · *.p12 · secrets.* · credentials.*) · push protection · 들어갔다면 키부터 재발급 |
| 회사 · 고객 · 기관 내부 자료 · 계약서 · 사업계획서 | 비밀정보 유출 | raw/의 무시 폴더에만 · 가명 처리 사본 |
| 유료 자산(개인 · 조직 맞춤 운영체계 · 컨설팅 산출물) | 핵심 자산 | 공개할 70%와 남길 30%를 처음에 나눔 — 이 저장소는 공통 검증 지식만 |
| 특정 개인 · 기업을 식별해 지목한 민감 사례 | 명예훼손 위험 | "어느 서비스가"가 아니라 "이런 모양으로" |
| 실제 이메일 · 컴퓨터 이름이 든 커밋 작성자 | 공개 시 노출 | GitHub no-reply 주소로 작성자 설정 — 첫 커밋 전에 |

## 3 근거 — GitHub 공식 문서

- **라이선스가 없으면 기본 저작권법이 적용된다** — GitHub Docs「Licensing a repository」: 라이선스를 고를 의무는 없지만, 없으면 기본 저작권이 적용되어 남이 복제 · 배포 · 파생물 작성을 할 수 없다. 오픈소스 프로젝트라면 오픈소스 라이선스를 포함하기를 강력히 권한다 (2026-10-10 페이지 열람으로 문장 확인)
- **.gitignore** — 저장소 루트에 두고 커밋에서 뺄 파일 · 폴더를 적는다. 이미 커밋한 파일은 목록에 적어도 이력에 남는다
- **secret scanning · push protection** — 하드코딩된 자격증명 · 토큰이 push되는 것을 막는 기능. 이미 올라간 민감정보는 이력에서 완전히 지우기가 까다롭다(「Removing sensitive data from a repository」) → **첫 커밋 전 점검이 핵심**
- **CITATION 파일** — 저장소 루트의 CITATION.cff를 GitHub이 인식해 "이 저장소 인용" 안내를 띄운다 → 이 저장소의 [CITATION.cff](../CITATION.cff)

링크와 확인 로그 — [07-references.md](07-references.md)

## 4 이 저장소가 쓴 점검 절차(재현용)

1. 첫 커밋 전: 들어갈 파일 목록을 눈으로 끝까지 읽는다(`git add -n .`) · 빠지는 목록(`git status --short --ignored`)
2. 개인정보 · 비밀값 검색 — 이메일 패턴 · 휴대전화 · 주민번호 · 실명 · 기관명 · `api_key` · `token=` · `password` · 긴 무작위 문자열
3. 작성자 확인 — `git config --get user.email`이 `…@users.noreply.github.com`으로 끝나는가
4. 적대적 검토 요청문(고치지 말고 찾기만) — [github-guide](../github-guide/github-for-non-developers.md) 5절
5. 공개 뒤에도 같은 검색을 커밋마다 — 규칙은 CLAUDE.md에, 검사는 스크립트로

## 5 공개 가능 여부가 애매할 때

- "공개 자료의 요약"인지 "원문 복사"인지 애매하면 — 링크와 한 줄 요약만 두고 본문은 내 말로 다시 쓴다
- "가상 예시"인지 "실제 사례의 각색"인지 애매하면 — 식별 가능한 요소(기관 · 시기 · 금액 · 고유 상황)를 모두 바꾸고 첫 줄에 가상임을 적는다. 바꿀 수 없으면 싣지 않는다
- 라이선스가 CC BY-SA인 자료를 옮겨 담았는지 애매하면 — 이름 · 번호 · 링크만 남기고 설명을 지운다 → [license-guide](../license-guide/choose-a-license.md)
