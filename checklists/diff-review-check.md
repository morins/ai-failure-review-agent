# 끝난 뒤 diff — 요약 말고 바뀐 줄부터

> 에이전트의 요약이 아니라 diff와 파일 목록에서 내가 읽은 것으로 판정한다. 잘 읽히는 요약 뒤에 뜻밖의 파일이 있다.

## 1 목록부터

- [ ] **고친 파일 · 새로 생긴 파일 · 지워진 파일**로 나눈 목록을 먼저 받는다 — 새로 생긴 파일은 diff에 나오지 않고 목록에만 나온다
- [ ] **권한의 한계 밖**의 파일이 있는가 — 시키지 않은 변경이 되돌릴 첫 후보
- [ ] 파일 수가 예상보다 많으면 멈추고 묻는다 — "왜 이 파일을 고쳤는지 근거가 되는 줄을 보여줘"

요청문:

```text
마지막 커밋 이후 바뀐 것을 전부 보여줘. 고친 파일, 새로 생긴 파일, 지워진 파일로 나눠 목록을 먼저 보여주고, 고친 파일은 diff로, 새로 생긴 파일은 내용 요약으로 보여줘. 내가 권한의 한계로 적은 범위를 벗어난 변경이 있으면 따로 표시해줘. 아직 커밋하지 마.
```

## 2 diff 읽는 법

```
diff --git a/CLAUDE.md b/CLAUDE.md     ← 어느 파일인지 — 파일 이름만 읽음
index 7b08eba..3891fa5 100644          ← 내부 번호 — 건너뜀
--- a/CLAUDE.md                        ← 건너뜀
+++ b/CLAUDE.md                        ← 건너뜀
@@ -3,3 +3,4 @@                        ← 몇 번째 줄 근처인지 — 위치만
 (바뀌지 않은 줄)                       ← 기호 없음 = 앞뒤 문맥
+(새로 들어간 줄)                       ← 초록 + = 읽음
-(빠진 줄)                              ← 빨강 - = 읽음
```

- [ ] 읽을 곳은 **+ 줄과 - 줄뿐**. 머리글은 건너뛴다
- [ ] 한 줄 고치기 = 빨강 하나 + 초록 하나. 내가 의도한 줄만 바뀌었는가
- [ ] `\ No newline at end of file` — 정상(마지막 줄 끝에 줄바꿈이 없었던 것)
- [ ] `Binary files … differ` — 한글(.hwp) · 워드(.docx) · PDF는 바뀌었다는 사실만 보인다. 작업 원고는 .md로

## 3 완료의 모습과 대조

- [ ] 내가 적은 **완료의 모습**을 항목마다 통과 · 미통과로 — 에이전트의 "다 했다"가 아니라 내 눈으로
- [ ] 결과 파일을 **직접 연다** · 돌려 본다 · 센다
- [ ] 검증 스크립트가 있으면 **출력을 그대로** 본다(요약 말고)
- [ ] 규칙 파일에 더한 줄이 있다면 **이번 결과에서 지켜졌는가** — 규칙을 외워 말하게 하지 않고 일을 시킨 결과로 확인
- [ ] "확인했다"고 적힌 문장마다 **무엇을 열어 대조했는지** — 근거가 없으면 〔확인 못 함〕으로 고쳐 적는다

## 4 판정 — 되돌리기 신호등

| 신호 | 하는 일 | 남는 것 | 이 체크리스트에서 |
|---|---|---|---|
| 초록 — revert | 되돌리는 커밋을 하나 더 만든다 | 무엇을 했고 왜 되돌렸는지가 이력에 남음 | **사용** |
| 노랑 — restore | 커밋하지 않은 변경을 버린다 | 버린 것은 되살릴 수 없음 | 조심 |
| 빨강 — reset | 커밋 자체를 없앤다 | 이력이 사라짐 | **사용 안 함** |

- **전부 받아들일 때** — 무엇을 왜 받아들였는지 드러나는 메시지로 커밋
- **일부만** — 받아들일 파일만 먼저 커밋 → 나머지는 "받아들이지 않은 변경"으로 커밋한 뒤 그 커밋을 취소하는 새 커밋(revert)
- **전부 되돌릴 때** — "에이전트 작업 결과 — 받아들이지 않음"으로 커밋한 뒤 revert. 받아들이지 않을 변경도 먼저 커밋하는 이유: 커밋하지 않고 버리면 에이전트가 무엇을 했는지의 기록이 사라진다

## 5 기록

- [ ] 바꾼 것(파일 이름과 내용) · 받아들인 것과 이유 · 되돌린 것과 이유(없으면 "없음"과 근거)
- [ ] 범위 밖 변경이 있었나 · 완료의 모습이 실제로 되었나(내 눈으로 확인한 방법)
- [ ] **다음에 맡길 때 요청문에서 고칠 한 줄** — 같은 지적을 두 번 하게 되면 고칠 곳은 결과물이 아니라 요청문 · 규칙 파일
