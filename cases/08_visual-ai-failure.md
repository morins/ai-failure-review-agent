# 08 · 이미지 · 영상 — 손 · 글자 · 로고 · 차트 수치가 깨진다

> 한 줄: 이미지 모델은 '그럴듯한 픽셀'을 고른다. 글자는 글자 모양으로, 손은 손 모양으로 그릴 뿐 읽거나 세지 않는다. 사실을 담는 그림은 생성하지 않고 그린다.

## 증상 — 겉으로 보이는 모습

- **손가락이 여섯 개** · 팔이 셋 · 물건을 쥔 손이 물건을 통과한다
- **글자가 깨진다** — 특히 한글 · 작은 글자 · 간판 · 표지의 제목. 비슷한 모양의 가짜 글자
- **로고가 변형된다** — 실제 로고와 비슷하지만 다른 로고. 쓰면 상표 문제
- **캐릭터 일관성이 무너진다** — 같은 인물이 컷마다 다른 얼굴 · 옷 · 나이
- **차트 · 지도 · 도표의 수치가 임의다** — 막대 높이와 숫자가 안 맞고, 지도의 경계가 틀리고, 축 눈금이 불규칙
- **물리가 틀린다** — 그림자 방향 · 반사 · 액체 · 계단 수가 어긋남
- 영상에서 **장면 전환 때 물건이 바뀐다** · 걷는 다리가 꼬인다 · 글자가 흐른다
- 결과물이 **매번 다르다** — 같은 프롬프트로 같은 결과를 다시 만들 수 없다

## 실제 모습 — 가상 예시

가상 시나리오 — 보고서 삽도를 이미지 모델로 만들었다. 막대그래프의 막대 다섯 개 위에 숫자가 적혀 있었는데, 막대 높이와 숫자가 서로 맞지 않았고 축 라벨의 한글 두 글자가 비슷한 모양의 가짜 글자였다. 인쇄 직전에 발견했다. 처방은 "프롬프트를 더 정교하게"가 아니라 **수치와 글자는 코드로 그린다**였다 — 그림의 분위기만 모델이 맡고, 숫자 · 라벨 · 정렬은 그리기 코드가 맡는다. 결과는 재현 가능하고 글자가 깨지지 않는다.

## 왜 생기나 — 원리

- **픽셀 패턴 예측** — 이미지 모델도 '이 자리에 올 법한 픽셀'을 고른다. 손가락 수를 세거나 글자를 읽는 과정이 없다.
- **글자는 모양으로만 학습** — 글자가 "읽히는 기호"가 아니라 "글자처럼 생긴 질감"으로 학습된다. 학습 데이터가 적은 문자(한글 등)일수록 깨진다.
- **세계 모델이 없다** — 물리 · 해부 · 지리를 아는 것이 아니라 흔한 장면을 재현한다. 흔하지 않은 각도 · 동작에서 무너진다.
- **일관성은 기억이 아니다** — 컷마다 새로 생성하므로 '같은 인물'을 기억하지 않는다. 레퍼런스 이미지 · 시드 고정이 없으면 매번 다른 사람이다.
- **차트는 '차트처럼 생긴 그림'** — 데이터에서 그린 것이 아니므로 수치와 그림이 독립이다.

## 어떻게 잡나 — 확인 순서

1. **확대** — 100%보다 크게 확대해서 본다. 손 · 글자 · 로고 · 배경의 작은 문자 · 액세서리.
2. **센다** — 손가락 · 사람 · 물건 · 계단 · 창문. 세어 보면 보인다.
3. **읽는다** — 그림 속 모든 글자를 읽어 본다. 읽히지 않는 글자는 가짜다.
4. **차트는 데이터와 대조** — 막대 높이 · 선의 위치가 원자료 수치와 맞는지 자로 재듯 본다. 축 눈금 간격이 같은지.
5. **로고 · 상표 · 실존 인물** — 실제와 비슷하면 쓰지 않는다. 생성물이라도 상표 · 초상 규칙은 동일하다.
6. **영상은 컷마다** — 장면 전환 전후의 인물 · 소품 · 배경 문자를 캡처해 나란히 놓는다.
7. **사실로 쓰일 그림인가** — 지도 · 도표 · 설계도 · 통계 그래프는 생성물을 쓰지 않는다. 분위기 삽화만 생성한다.

## 예방 규칙 — 요청문 · 규칙 파일 · 장치

- **글자 · 수치는 코드로** — 라벨 · 숫자 · 축 · 표는 그리기 코드(또는 디자인 도구)가 그리고, 모델은 배경 · 분위기만. 깨짐 없음 · 재현 가능 · 수정 가능.
- **샷 단위로 쪼갠다** — 한 프롬프트에 여러 요구를 넣지 않는다. 인물 · 배경 · 소품을 분리해 생성하고 합친다.
- **레퍼런스 고정** — 인물 · 소품은 참조 이미지를 고정하고 컷마다 같은 참조를 준다. 시드가 있으면 적어 둔다.
- **제약을 프롬프트에** — "손은 주머니에" · "글자 없음" · "로고 없음"처럼 **없애는 지시**가 고치는 지시보다 잘 듣는다.
- **검수 체크리스트를 산출물에 붙인다** — 손 · 글자 · 로고 · 수치 · 일관성 다섯 칸을 컷마다 통과 · 미통과로.
- **생성물 표시** — 보고서 · 콘텐츠에 쓸 때는 생성 여부를 밝힌다([ethics/ai-use-disclosure-guide.md](../ethics/ai-use-disclosure-guide.md)). 사실로 오해될 그림(지도 · 사진 같은 삽화)은 특히.
- **프롬프트 · 시드 · 모델 · 날짜를 기록** — 같은 결과를 다시 만들어야 할 때 필요하다.

## 되풀이되면 — 결과물이 아니라 장치를 고친다

깨진 글자를 매번 포토샵으로 고치고 있다면, 고칠 곳은 그림이 아니라 **글자를 누가 그리느냐**다. 글자 · 수치를 코드로 옮기면 다음 삽도부터 같은 문제가 나지 않는다.

## 부록 · 가상 사례 모음 — C-067 ~ C-078 (12건)

> 아래는 2026-10-10 리서치 컬렉션(ai-failure-patterns-research.pdf와 함께 받은 번들)에서 결합한 짧은 가상 예시다. 실제 인물 · 기관 · 고객과 무관하며, 번호(C-###)는 인용할 때 쓰는 고정 번호다. 각 예시는 상황 · 증상 · 원인 · 확인 방법 · 예방 규칙 다섯 줄로 되어 있고, 위의 본문보다 짧은 대신 장면이 다양하다.

#### C-067 · 손가락 개수 오류
- 상황(가상): 인물 사진을 생성.
- 증상: 손가락이 6개거나 손 모양이 어색함.
- 원인: 손 구조 학습 한계.
- 확인 방법: 손·발을 확대해 확인.
- 예방 규칙: 손이 작게 나오는 구도로 하거나 후보정한다.

#### C-068 · 이미지 속 글자 깨짐
- 상황(가상): 포스터에 문구를 넣어 생성.
- 증상: 글자가 뒤섞이거나 의미 없는 문자로 깨짐.
- 원인: 텍스트 렌더링 불안정.
- 확인 방법: 글자를 확대해 철자 확인.
- 예방 규칙: 글자는 생성 후 편집 도구로 다시 넣는다.

#### C-069 · 로고 왜곡
- 상황(가상): 브랜드 목업 이미지를 생성.
- 증상: 로고 형태·비율이 변형됨.
- 원인: 로고 재현 부정확.
- 확인 방법: 원본 로고와 대조.
- 예방 규칙: 로고는 원본 파일을 합성한다.

#### C-070 · 인물 일관성 붕괴
- 상황(가상): 여러 장면의 같은 인물을 생성.
- 증상: 장면마다 얼굴이 달라짐.
- 원인: 참조 이미지 미사용.
- 확인 방법: 장면 간 얼굴 비교.
- 예방 규칙: 참조 이미지를 지정해 일관성을 잠근다.

#### C-071 · 시대·복식 불일치
- 상황(가상): 특정 시대 배경 이미지를 생성.
- 증상: 현대 복식·소품이 섞임.
- 원인: 시대 제약 미지정.
- 확인 방법: 시대 고증 요소 확인.
- 예방 규칙: 시대·복식 조건을 명시한다.

#### C-072 · 배경·사물 개수 오류
- 상황(가상): "사과 3개"를 요청.
- 증상: 2개 또는 4개가 생성됨.
- 원인: 개수 조건 반영 실패.
- 확인 방법: 개수를 세어 확인.
- 예방 규칙: 중요한 개수는 생성 후 확인·수정한다.

#### C-073 · 부자연스러운 신체 비율
- 상황(가상): 전신 인물을 생성.
- 증상: 팔다리 길이·비율이 어색함.
- 원인: 전신 구도 학습 한계.
- 확인 방법: 실루엣·비율 확인.
- 예방 규칙: 구도를 단순화하고 후보정한다.

#### C-074 · 텍스트-이미지 불일치
- 상황(가상): 특정 행동을 지정.
- 증상: 요청과 다른 행동이 생성됨.
- 원인: 프롬프트 해석 차이.
- 확인 방법: 요청 요소와 결과 대조.
- 예방 규칙: 핵심 요소를 명사로 구체적으로 지정한다.

#### C-075 · 워터마크·서명 오염
- 상황(가상): 배경 이미지를 생성.
- 증상: 원치 않는 워터마크·문자 흔적이 포함됨.
- 원인: 학습 데이터 흔적.
- 확인 방법: 모서리 확대 확인.
- 예방 규칙: 생성 후 모서리·배경을 점검한다.

#### C-076 · 영상 프레임 간 떨림
- 상황(가상): 짧은 클립을 생성.
- 증상: 인물·배경이 프레임마다 흔들림.
- 원인: 프레임 간 일관성 부족.
- 확인 방법: 프레임 단위 확인.
- 예방 규칙: 샷을 짧게 나누고 참조를 고정한다.

#### C-077 · 생성물 미표시
- 상황(가상): 홍보물에 AI 이미지를 사용.
- 증상: 생성 사실 표시가 없음.
- 원인: 표시(라벨·메타데이터) 누락.
- 확인 방법: 메타데이터·라벨 확인.
- 예방 규칙: 생성 사실을 표시하고 C2PA 정보를 붙인다.

#### C-078 · 학습데이터 저작권·초상권 위험
- 상황(가상): 특정 작가·인물 스타일을 요청.
- 증상: 실존 작품·인물과 유사해 권리 침해 소지.
- 원인: 스타일 모방·실존 인물 재현.
- 확인 방법: 원작·인물과 유사도 확인.
- 예방 규칙: 실존 스타일·인물은 피하거나 권리를 확인한다.
