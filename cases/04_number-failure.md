# 04 · 수치 오류 — 합계 · 비율 합 · 단위 · 기간이 어긋난다

> 한 줄: 모델은 계산기가 아니다. 숫자도 '다음 조각'으로 고른다. 합계가 맞는 것처럼 보이는 것과 맞는 것은 다르다.

## 증상 — 겉으로 보이는 모습

- **선정률 30%** — 그런데 본문의 두 수(12,050 ÷ 48,200)로 계산하면 25.0%
- **비중의 합이 100이 아니다** — 27.2 + 22.5 + 35.3 + 16.1 = 101.1인데 "합계 100.1%"
- **근거 없는 배수** — "전월 대비 두 배"인데 전월 값이 어디에도 없다
- **단위 혼동** — 백만 원 표를 억 원으로 옮기며 자릿수가 밀림 · 천 명을 명으로
- **%와 %p** — 10%에서 12%가 된 것을 "20% 증가"라고도, "2% 증가"라고도 쓴다
- **기간 불일치** — 8월 자료를 9월 기준으로 · 회계연도와 역년 혼동
- **표를 옮길 때 열이 어긋남** — 한 줄 아래 값을 가져오거나 두 열을 바꿈
- 계산 과정을 보여 달라고 하면 과정은 그럴듯한데 **중간값이 다르다**

## 실제 모습 — 가상 예시

[raw/예시_AI답변_02_통계요약.md](../raw/예시_AI답변_02_통계요약.md)의 AI 요약 23행:

> 지원액의 지역별 비중은 가 27.2%, 나 22.5%, 다 35.3%, 라 16.1%로 합계 100.1%다.

원자료 표로 계산하면 나 지역은 1,225 ÷ 5,700 = **21.5%**다. 네 값을 더하면 101.1이지 100.1이 아니다. 문장은 합계까지 적어 더 믿음직해 보인다. 같은 파일 19행의 "선정 건수는 전월 대비 두 배로 증가"는 전월 선정 값이 원문에 없어 **계산할 수조차 없다** — 〔확인 못 함〕이 아니라 '근거 없음'으로 미통과.

[raw/예시_AI답변_01_정책브리프.md](../raw/예시_AI답변_01_정책브리프.md) 13행의 선정률 30%는 같은 문장 안의 두 수로 25.0%임이 드러난다 — **원문만으로도 잡히는** 오류다.

## 왜 생기나 — 원리

- **숫자도 토큰이다** — 25.0%와 30%는 모델에게 '그럴듯함'의 차이일 뿐 계산 결과가 아니다. 자주 본 숫자(25, 30, 50)가 선택되기 쉽다.
- **합계 문장은 형식이다** — "합계 100%"는 비중 문장 끝에 자주 오는 조각이라 값과 무관하게 붙는다.
- **표 읽기는 위치 맞추기** — 열 · 행을 눈으로 맞추는 일에서 한 칸 밀리면 전부 밀린다. 모델에게 표는 문자열이다.
- **단위 환산은 두 단계** — 숫자 선택과 단위 선택이 따로 일어난다. 환율 · 자릿수는 특히 취약하다.
- **%와 %p는 학습 데이터에서도 혼용된다** — 모델은 흔한 쪽을 따른다.

## 어떻게 잡나 — 확인 순서

1. **다시 계산** — 본문 안에 분자 · 분모가 있으면 직접 나눈다. 곱셈 · 합계는 계산기로. 원문만으로 잡히는 오류가 가장 많다.
2. **비율의 합** — 비중은 100(반올림 오차 ±0.1~0.2), 증감률의 합은 의미가 없다(합계를 검증 기준으로 삼지 않는다).
3. **단위 열** — 표 머리의 단위(백만 원 · 천 명)와 문장의 단위(억 원 · 명)를 나란히 놓는다. 자릿수를 센다.
4. **기간** — 표 제목의 기간과 문장의 기준일. 전월 · 전년 값이 **실제로 원자료에 있는가**.
5. **%와 %p** — 비율의 차이는 %p, 비율의 비율은 %. 문장이 어느 쪽인지 원자료로 확인한다.
6. **분모** — 선정률의 분모가 신청 건수인가 접수 건수인가. 정의가 바뀌면 값이 바뀐다.
7. **무작위 대조** — 표를 옮긴 결과는 원자료와 무작위 10칸을 대조한다. 행 수 · 열 합계부터.

## 예방 규칙 — 요청문 · 규칙 파일 · 장치

- **계산은 스크립트로** — 수치가 있는 일은 모델이 '말로' 계산하게 두지 않는다. 코드를 쓰게 하고, 원자료에서 읽어 계산한 결과만 쓴다.
- **대조 스크립트를 완료 정의에** — "행 수 · 열 합계가 원자료와 일치하지 않으면 멈춘다." 안 맞으면 결과를 내보내지 않는 장치.
- **요청문** — "수치는 raw/ 표에서만 가져오고, 모든 수치 옆에 (표 번호 · 행 · 열)을 적어라. 계산 과정은 식으로 보여라."
- **규칙 파일 한 줄** — "비율 열은 합계를 내지 않는다 · 모든 수치에 단위와 기준일을 붙인다."
- **출력 양식에 단위 · 기준일 열** — 빈칸이 보이게.
- **전월 · 전년 비교는 두 값을 모두 표에** — 하나만 있는 비교 문장은 통과시키지 않는다.

## 되풀이되면 — 결과물이 아니라 장치를 고친다

수치를 손으로 고쳐 넣는 일이 두 번째면 고칠 곳은 숫자가 아니라 **계산을 누가 하느냐**다. 원자료 → 스크립트 → 표 → 대조 스크립트의 사슬을 만들면, 다음 달에는 "이번 달 것"이라는 한마디로 같은 형식 · 같은 검증 · 원자료 무손상이 된다.

## 부록 · 가상 사례 모음 — C-041 ~ C-052 (12건)

> 아래는 2026-10-10 리서치 컬렉션(ai-failure-patterns-research.pdf와 함께 받은 번들)에서 결합한 짧은 가상 예시다. 실제 인물 · 기관 · 고객과 무관하며, 번호(C-###)는 인용할 때 쓰는 고정 번호다. 각 예시는 상황 · 증상 · 원인 · 확인 방법 · 예방 규칙 다섯 줄로 되어 있고, 위의 본문보다 짧은 대신 장면이 다양하다.

#### C-041 · 합계가 맞지 않는 표
- 상황(가상): 항목별 실적표를 만들고 합계를 요청.
- 증상: 행의 합이 합계 행과 다름.
- 원인: 합계를 계산하지 않고 추정.
- 확인 방법: 열 합계를 원자료로 재계산.
- 예방 규칙: 합계는 스크립트/계산기로 다시 검산한다.

#### C-042 · 단위 혼동(천 원 ↔ 원)
- 상황(가상): 예산 표를 정리.
- 증상: 단위가 섞여 10배 이상 차이.
- 원인: 단위 표기 미확인.
- 확인 방법: 각 셀 단위 표기 확인.
- 예방 규칙: 단위를 셀·머리글에 고정한다.

#### C-043 · 기간 기준 혼동
- 상황(가상): 연간 실적을 집계.
- 증상: 회계연도와 역년을 혼합.
- 원인: 기간 정의 불일치.
- 확인 방법: 기간 정의를 원자료에서 확인.
- 예방 규칙: 기간 정의(회계/역년)를 명시한다.

#### C-044 · 중복 집계
- 상황(가상): 여러 파일을 합쳐 건수를 계산.
- 증상: 같은 항목이 두 번 세어져 건수가 부풀려짐.
- 원인: 중복 제거 없이 합산.
- 확인 방법: 고유 키 기준 재집계.
- 예방 규칙: 중복 제거 기준을 정하고 검증한다.

#### C-045 · 반올림 방향 오류
- 상황(가상): 비율·금액을 반올림.
- 증상: 항목 합이 전체와 어긋남.
- 원인: 각 항목을 먼저 반올림.
- 확인 방법: 전체 기준 반올림과 비교.
- 예방 규칙: 반올림은 전체에서 한 번만 한다.

#### C-046 · 퍼센트와 퍼센트포인트 혼동
- 상황(가상): 증가율을 서술.
- 증상: %p 상승을 % 상승으로 표기.
- 원인: 두 개념 혼용.
- 확인 방법: 기준값 대비 계산.
- 예방 규칙: %와 %p를 구분해 표기한다.

#### C-047 · 기준 연도 불일치
- 상황(가상): 성장률을 계산.
- 증상: 비교 기준 연도가 다름.
- 원인: 기준 미확인.
- 확인 방법: 원자료의 연도 확인.
- 예방 규칙: 기준 연도를 표에 명시한다.

#### C-048 · 인구·표본 기준 혼동
- 상황(가상): 비율을 계산.
- 증상: 전체 인구와 표본을 혼동.
- 원인: 분모 정의 불명.
- 확인 방법: 분모 정의 확인.
- 예방 규칙: 분모(모집단/표본)를 명시한다.

#### C-049 · 환율·통화 무시
- 상황(가상): 국제 비교 표를 작성.
- 증상: 환율 적용 없이 금액을 비교.
- 원인: 통화 환산 누락.
- 확인 방법: 적용 환율·시점 확인.
- 예방 규칙: 환율과 기준일을 명시한다.

#### C-050 · 누락된 항목
- 상황(가상): 원자료 전체를 요약.
- 증상: 일부 행·항목이 빠져 총계가 작음.
- 원인: 샘플만 반영.
- 확인 방법: 원자료 행 수와 대조.
- 예방 규칙: 행 수를 대조하는 검증 단계를 둔다.

#### C-051 · 잘못된 출처 귀속 수치
- 상황(가상): 수치에 출처를 달라고 요청.
- 증상: 같은 수치를 다른 기관에 귀속.
- 원인: 출처 혼동.
- 확인 방법: 원 출처에서 수치 확인.
- 예방 규칙: 수치-출처 짝을 원문에서 확인한다.

#### C-052 · 소수점·자릿수 오류
- 상황(가상): 계산 결과를 옮겨 적음.
- 증상: 소수점 위치가 달라 10배 차이.
- 원인: 옮겨 적기 오류.
- 확인 방법: 자릿수 재확인.
- 예방 규칙: 계산값은 원 계산식과 함께 남긴다.
