# 맡기기 전 — 요청문 · 커밋 · 되돌릴 수 있는가

> 맡기는 범위는 되돌릴 수 있고 내가 검토할 수 있는 데까지. 요약하면 — **맡기기 전에 저장점을 만들고, 끝나면 바뀐 줄을 읽는다.**

## 0 이 일을 맡겨도 되는가

- [ ] **검증할 수 있는 일인가** — 결과를 원자료 · 원문 · 개수와 대조할 수 있는 일(표 옮기기 · 인용 확인 · 파일 정리)은 맡기기 쉽다. 좋다 · 설득력 있다 · 중요하다처럼 채점 기준이 없는 일은 **기준부터 만든다**
- [ ] **되돌릴 수 있는가** — 원본은 잠그고(권한 deny) 사본에서 일하게 한다. 되돌릴 수 없는 일(발송 · 게시 · 삭제)은 사람이 직접
- [ ] **내가 검토할 수 있는 크기인가** — 바뀐 줄을 한 번에 읽기 어려울 만큼 많다면 일을 더 작게 쪼갠다. 읽지 못한 변경은 판정할 수 없다
- [ ] **스스로 할 일을 따로 정한다** — 이해가 필요한 일(새로 배우는 것 · 판단이 쌓이는 것)은 통째로 넘기지 않는다. 넘긴 만큼 이해가 남지 않는다

## 1 요청문 다섯 칸

| 칸 | 적을 것 | 빠지면 |
|---|---|---|
| **목적과 이유** | 무엇을 위해 · 왜 지금 | 엉뚱한 방향으로 최적화 |
| **할 일** | 내 폴더의 파일 이름으로 | "이 폴더 자료"가 무엇인지 추측 |
| **권한의 한계** | 고쳐도 되는 것 · 고치면 안 되는 것 · 하면 안 되는 명령(커밋 · 삭제 · 외부 전송) · "저장할지는 내가 본 뒤에" | **금지가 가장 자주 빠지고 사고는 거기서 난다** |
| **완료의 모습** | 무엇이 어떤 상태면 끝인지 — 눈으로 확인할 수 있게 · 숫자로 | "다 됐다"를 검증할 수 없음 |
| **필요한 산출물** | 남길 파일의 이름과 위치 · 무엇을 바꿨는지 세 줄 요약 | 결과가 대화 속에만 남음 |

양식:

```text
다음 일을 부탁한다. 실행 전에 네가 이해한 목표 · 범위 · 완료 조건을 각각 한 줄로 먼저 보내고, 내가 "진행"이라고 답한 뒤에 시작한다.

목적: (이 일이 왜 필요한지 · 결과를 누가 어떻게 쓰는지)
작업: (내 폴더의 파일 이름으로 — 입력 파일 · 출력 파일)
허용 범위: 쓰기는 (폴더)에만. (원본 폴더) · (규칙 파일)은 읽기만. 삭제 금지. 커밋 · 되돌리기 · 푸시 금지 — 저장 여부는 내가 바뀐 줄을 본 뒤 결정.
완료 조건: (눈으로 확인할 수 있는 상태 — 파일 · 행 수 · 검사 결과)
산출물: (파일 이름 · 위치) + 바꾼 것 세 줄 요약
```

## 2 맡기기 직전

- [ ] **예상을 먼저 적는다** — 직접 하면 걸리는 시간 · 한 번에 될 것 같은 정도(열 번 중 몇 번) · 요청과 확인에 드는 시간. 끝난 뒤 실제와 나란히 놓는다
- [ ] **커밋한다** — "맡기기 전 저장". 커밋하지 않은 변경이 남아 있지 않은지 확인. 되돌아갈 지점이 생긴다
- [ ] **규칙이 파일에 있는가** — 이번 일에 꼭 지켜야 할 규칙이 대화가 아니라 규칙 파일(CLAUDE.md)에 있는지. 새 대화를 열면 그 파일이 처음부터 읽힌다
- [ ] **권한 설정** — 원본 폴더 편집 deny · 삭제 명령 deny · 외부 전송 ask. 되돌릴 수 있는 범위까지만 허용
- [ ] **시작 전 요약 확인** — 실행 전에 받은 목표 · 범위 · 완료 조건 요약이 내 뜻과 같은지. 다르면 시작 전에 바로잡는다 — 방향을 가장 싸게 바꿀 수 있는 자리

## 3 맡기는 동안

- [ ] 권한 창이 뜨면 **명령을 읽고** 내가 적은 권한의 한계와 같은 종류인지 대조한 뒤 허용
- [ ] 원본 폴더를 고치려 하면 거부 → "out/에만 써줘"
- [ ] 같은 오류가 반복되면 오류 문구를 그대로 붙여 원인부터 설명하게 한다 · 두 번 넘으면 새 대화에서 요청문을 다시 쓴다
