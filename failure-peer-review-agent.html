파일을 올리면 열 가지 실패 유형으로 의심 지점을 표시하고, 원문 대조와 재계산으로 고치는 다섯 단계 관문을 보여 줍니다. 본인 API 키를 넣으면 실제 모델이 텍스트 파일을 검토합니다(선택). 통과 판정은 사람이 합니다.

EN Drop a file to see suspected issues marked by ten failure types and a five-gate review loop (upload → review → detect → repair → pass). Demo by default — nothing is sent anywhere. With your own API key (optional) a real model reviews text files. The pass verdict always belongs to a human.

논문 · 보고서 · 표 · 이미지 · 발표 자료 · 코드, 형식과 무관하게 받습니다

DEMO기본은 브라우저 안에서만 도는 시뮬레이션입니다 — 실제 AI 모델을 부르지 않고 파일 내용을 읽지도 않으며(이름 · 크기만 사용) 어디에도 전송하지 않습니다. 아래 실제 모델 연결(선택)에 본인 API 키를 넣으면 .txt · .md · .csv · .json 파일에 한해 실제 모델이 검토합니다. 어느 쪽이든 통과 판정은 사람이 합니다.
EN Default mode is a browser-only simulation: no AI model is called, file contents are never read (name and size only), nothing is sent anywhere. Enter your own API key under "실제 모델 연결(선택)" to have a real model review .txt · .md · .csv · .json files. Either way, the pass verdict is yours.
OPTIONAL실제 모델 연결(선택) — 본인 API 키로 텍스트 파일을 실제 검토설정 없음 · 데모 모드
세 칸을 채우면 실제 모델 모드가 켜집니다
  • 키와 파일 내용은 이 브라우저에서 본인이 지정한 제공자에게만 전송됩니다. 이 페이지는 서버가 없어 운영자에게는 아무것도 가지 않습니다.
  • 개인정보 · 기관 내부 자료는 넣지 마세요 — 제공자에게 전송되는 순간 회수할 수 없습니다.
  • 실제 검토는 텍스트 파일(.txt · .md · .csv · .json, 앞 60,000자)만 합니다. 그 외 형식은 데모로 처리됩니다.
  • 모델도 틀립니다 — 결과는 "확인할 지점" 목록이며 통과 · 미통과 판정은 사람이 합니다.
  • 모델이 든 인용은 올린 파일과 대조해 줄 번호(L17)를 붙입니다. 원문에서 찾지 못한 인용은 〔원문에 없음〕으로 표시되고, 검사기(tools/check_review_sheet.py)는 그 행의 '통과'를 막습니다.
  • 브라우저에서 직접 호출할 수 없는 제공자(CORS 차단)는 연결 시험에서 실패합니다. 그때는 데모 모드로 돌아갑니다.

01 · 검증 관문

다섯 단계, 하나의 관문

각 단계는 통과 조건을 갖습니다. 조건을 못 넘으면 그 자리에서 멈추고, 고친 뒤 다시 올립니다.

STEP 01 ✔

업로드

자료를 넣는다. 원자료와 결과물을 함께 둔다.

관문 · 원자료 확보
STEP 02 ✔

에이전트 검토

읽고 구조를 잡는다. 출처 · 수치 · 맥락을 뽑아 표시한다.

관문 · 주장과 근거 분리
STEP 03 ✔

실패 감지

열 유형으로 의심 지점을 표시한다. 지우지 않고 레드 표시로 남긴다.

관문 · 의심 지점 목록
STEP 04 ✔

보완

원문을 열어 대조하고, 숫자를 다시 계산한다. 근거 없는 항목은 삭제한다.

관문 · 원문 대조 완료
STEP 05 ✔

통과

기준을 통과한 결과만 남는다. 사람이 최종 판정한다.

관문 · 사람의 판정
02 · 전환

실패를 성공으로 바꾸는 여덟 가지

왼쪽은 감지된 실패, 오른쪽은 관문을 통과한 결과입니다.

감지 · 환각존재하지 않는 논문을 인용했다
→
통과 · 원문 대조원문이 확인된 인용만 남았다
감지 · 수치표의 합계가 행 합과 다르다
→
통과 · 재계산원자료로 다시 계산해 일치했다
감지 · 맥락다른 나라 기준으로 설명했다
→
통과 · 맥락 고정대상 국가·시점 기준으로 다시 썼다
감지 · 완료 선언확인하지 못한 항목을 "확인 완료"라고 적었다
→
통과 · 완료 정의 대조항목마다 근거를 붙이고 못 연 것은 〔확인 못 함〕으로 남겼다
감지 · 긴 대화아침에 정한 규칙이 오후 결과에서 사라졌다
→
통과 · 규칙 파일규칙을 파일로 옮겨 새 대화마다 다시 읽게 했다
감지 · 이미지생성 이미지의 글자가 깨졌다
→
통과 · 재작업글자를 다시 넣고 생성 사실을 표시했다
감지 · 자율성범위 밖 파일까지 고쳤다
→
통과 · 권한 준수허용 범위만 바꾸고 이력으로 남겼다
감지 · 항목 지정세부 A·B·C를 지정하지 않아 임의로 A에서 C로 건너뛰었다
→
통과 · 항목 명시세부 항목을 모두 지정해 단계를 건너뛰지 않았다

04 · 통과 기준

관문을 넘는 여섯 조건

하나라도 빠지면 통과가 아닙니다. 전부 확인해야 파란 신호가 켜집니다.

사실 · 출처

출처를 열어 원문에 그대로 있는지 확인했다

맥락 · 적용

국가·시점·대상·단위가 요청과 맞는지 확인했다

수치 · 데이터

행 수·합계를 원자료로 다시 계산했다

항목 지정

세부 A·B·C를 빠뜨리지 않고 모두 지정했다

책임 · 판정

내 이름으로 책임질 수 있는 상태인가

공개 가능

개인정보·비밀값·내부자료·타인 원문이 없는가

빨강은 감지, 파랑은 통과.

실패를 지우지 않고 표시한 뒤, 원문과 대조해 고친 것만 파란 신호를 켭니다. 이 화면이 그 판정 과정의 시각화입니다. 최종 판정 칸은 사람이 채웁니다.
