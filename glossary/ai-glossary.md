# AI 용어 사전 — 뜻보다 "모르면 생기는 실수"

> 용어를 아는 것과 적용 조건을 판단하는 것은 다르다. 그래서 칸을 하나 더 뒀다 — 이 말을 모르면 **어떤 실수를 하는가**, 그리고 **어떻게 막는가**. 내 폴더의 실물(파일 이름)을 붙일 수 있어야 안 것이다.

## 모델의 원리

| 용어 | 뜻 | 모르면 생기는 실수 | 예방 |
|---|---|---|---|
| **다음 토큰 예측** | 모델은 지식을 꺼내는 것이 아니라 가장 그럴듯한 다음 조각을 고른다 | 유창한 문장을 맞다고 믿는다 | 문장의 매끄러움을 근거로 삼지 않는다 · 수치 · 출처는 원문과 대조 |
| **토큰** | 모델이 읽고 쓰는 최소 단위(글자 · 단어 조각) | 긴 문서가 잘려 뒤쪽을 반영하지 못한 줄 모른다 | 긴 문서는 나눠 넣고 구간별 요약을 파일로 |
| **환각(hallucination)** | 없는 것을 있는 것처럼 — 맞는 조각을 잘못 이어 붙임 | 없는 논문 · 조문 · 수치를 그대로 옮긴다 | 실재 → 귀속 → 표기 순으로 확인 → [01](../cases/01_hallucination.md) |
| **학습 시점(cutoff)** | 모델이 학습한 자료의 마지막 시점 | 지난해 개정 · 올해 통계를 모델에게 묻는다 | 최신 자료는 내가 원문으로 준다 |
| **아첨(sycophancy)** | 사용자의 전제 · 결론에 맞춰 답하는 경향 | 내 결론을 먼저 말하고 확인받았다고 믿는다 | 결론을 먼저 말하지 않는다 · 반대 근거를 따로 시킨다 |
| **컨텍스트 창(context window)** | 모델이 한 번에 읽을 수 있는 글의 최대 분량 | 긴 대화 뒤 아침 규칙이 사라진 줄 모른다 | 규칙은 파일에 · 긴 일은 새 대화 → [07](../cases/07_context-loss.md) |
| **압축(compact)** | 긴 대화를 요약해 자리를 비우는 것 | 대화로만 한 지시가 요약에 섞여 사라진다 | 남길 것을 적어 압축 · 규칙 파일은 디스크에서 다시 읽힘 |
| **오프로딩(offloading)** | 중요한 것을 파일에 적어 두고 필요할 때 다시 읽는 것 | 모든 것을 대화에 두고 길어진다 | 작업노트.md · plan.md에 정한 것 · 남은 할 일 |
| **생각 수준(effort)** | 답하기 전에 쓰는 추론의 양 | 모든 일을 최고 수준으로 돌려 느리고 비싸거나, 설계를 가벼운 수준으로 돌려 뒤가 다 틀린다 | 기본값에서 시작해 품질이 좋아지는 일에만 올린다 |

## 지시와 환경

| 용어 | 뜻 | 모르면 생기는 실수 | 예방 |
|---|---|---|---|
| **프롬프트** | 모델에게 보내는 지시 | 한 줄 지시의 빈칸을 모델이 기본값으로 채운다 | 다섯 칸 요청문 → [delegation-check](../checklists/delegation-check.md) |
| **명세(spec) · 기획안** | 목표 · 범위 · 입력 · 처리 · 산출물 · 검증 · 하지 않을 것을 적은 문서 | "잘 정리해줘"처럼 판정할 수 없는 요구 | 02_기획안.md — 검증은 숫자 · 조건으로 |
| **규칙 파일(CLAUDE.md)** | 세션을 열 때마다 자동으로 읽히는 이 폴더의 규칙 | 매번 같은 설명을 되풀이한다 · 200줄 넘게 쌓아 절반이 무시된다 | 여러분만 아는 것만 · 다섯 줄 안팎 · 줄마다 "지우면 실수하나" |
| **하네스(harness)** | 모델 밖에서 일하는 방식을 정하는 장치 전체 — 규칙 · 권한 · 계획 · 검증 | 모델만 바꾸면 나아질 거라 믿는다 | 되풀이되는 실수 하나를 규칙 · 구조 · 검증으로 굳힌다 |
| **스캐폴딩** | 모델이 못 하는 것을 임시로 보완하는 구조 — 좋아지면 걷어냄 | 새 모델에서 짐이 되는 규칙을 계속 끌고 간다 | 규칙마다 "모델이 못 해서"인지 "알 수 없어서"인지 표시 |
| **에이전트** | 목표를 받고 도구를 루프로 돌려 스스로 진행하는 AI | 한 번 묻고 답하는 챗봇처럼 쓰거나, 반대로 검증 없이 통째로 맡긴다 | 명세 · 환경 · 검증은 사람이 쥔다 |
| **워크플로** | 미리 정한 순서대로 모델과 도구를 조율하는 것 | 모든 일에 에이전트를 쓴다 | 가장 단순한 해법부터 — 정리 · 매크로 · 한 번 호출 · 에이전트 순 |
| **스킬** | /이름으로 부르는 절차 파일 — 가끔 쓰는 긴 절차 | 긴 절차를 매번 설명하거나 규칙 파일에 넣어 길어진다 | 매번 지킬 규칙은 CLAUDE.md, 가끔 쓰는 절차는 스킬 |
| **서브에이전트** | 독립된 맥락과 권한을 가진 보조 에이전트 | 쓴 세션이 자기 결과를 검토하게 한다 | 검수는 새 맥락 · 읽기 전용으로 |
| **훅(hook)** | 정해진 시점(저장 직전 · 작업 종료 후)에 자동으로 걸리는 규칙 | 반드시 지킬 점검을 부탁(지시문)에만 둔다 | 반드시 지켜야 하는 점검은 훅으로 옮긴다 |
| **MCP · API** | 외부 도구 · 자료와 연결하는 규약 · 통로 | 모델의 기억으로 법령 · 통계를 답하게 한다 | 원문 조회 결과를 자료로 준다 |
| **RAG** | 외부 문서를 검색해 답변에 넣는 방식 | 검색이 틀리면 답도 틀린 줄 모른다 · 빠진 문서는 안 보인다 | 검색 결과의 출처 · 날짜 · 누락 건수를 본다 |
| **플랜 모드** | 편집을 막고 계획만 파일로 받아 승인하는 모드 | 방향이 틀린 채 한참 만든 뒤에 안다 | 큰 일은 계획 먼저 — 방향 오류를 싸게 잡는 장치 |
| **권한 모드 · 권한 규칙** | 묻기 · 막기 · 허용의 설정(deny → ask → allow) | 원본을 고치거나 지우는 것을 막지 못한다 | 원본 폴더 편집 deny · 삭제 deny · 외부 전송 ask |
| **관문(gate)** | 다음 단계로 넘어가기 전 반드시 통과해야 하는 검사 — 사람 관문 · 기계 관문 | 모든 단계에 사람이 서거나(병목), 아무 데도 안 선다 | 방향이 정해지는 곳(목차 · 설계)과 되돌릴 수 없는 일(발송 · 삭제) 직전에 |

## 검증과 기록

| 용어 | 뜻 | 모르면 생기는 실수 | 예방 |
|---|---|---|---|
| **검증(verification)** | 요구 · 명세대로 만들었는가 — 기계에 맡길 수 있다 | "테스트 통과"를 "쓸 수 있다"로 읽는다 | 기획안의 검증 기준 · 대조 스크립트 |
| **확인(validation)** | 받는 사람의 필요를 채우는가 — 사람의 일 | 맞는 답을 엉뚱한 질문에 낸다 | 받는 사람을 아는 사람이 본다 |
| **완료 정의** | 무엇이 어떤 상태면 끝인지 — 숫자 · 통과/실패로 | "다 됐다"를 검증할 수 없다 | plan.md의 완료 정의 절 |
| **기준선(baseline)** | 고치기 전에 잰 지금의 시간 · 오류 · 누락 | "좋아졌다"가 느낌으로만 남는다 | 먼저 재고, 같은 방법으로 다시 잰다 |
| **자기 채점** | 만든 쪽이 스스로 평가하는 것 | "됐다"로 기운다 · 통과시키려 테스트를 고친다 | 생성과 평가 분리 · 테스트 수정 금지 |
| **귀속(attribution)** | 그 문장이 정말 그 문서의 그 쪽에 있는가 | 주소가 열리면 통과를 준다 | 열어서 찾기(Ctrl+F) → [02](../cases/02_citation-failure.md) |
| **〔확인 못 함〕** | 확인하지 못했음을 적는 표시 — 실패가 아니라 정직한 기록 | 확인 못 한 것을 확인했다고 적는다 | 통과 · 미통과에는 근거, 못 열었으면 〔확인 못 함〕 |
| **재현성** | 다른 사람 · 다음 모델에서도 같은 결과가 나오는가 | 지시가 머릿속에만 있어 다음 사람이 못 만든다 | 지시 · 규칙 · 검증을 파일로 |
| **시드(seed)** | 생성 결과를 다시 만들기 위한 난수의 출발값 | 같은 그림을 다시 만들 수 없다 | 프롬프트 · 시드 · 모델 · 날짜를 기록 |

## 버전 관리 — 변경 이력을 남기는 장치

| 용어 | 뜻 | 익숙한 것으로 치면 | 모르면 생기는 실수 |
|---|---|---|---|
| **저장소(repository)** | 변경 이력이 기록되는 폴더 하나 — 이력은 숨은 폴더(.git)에 | 사진 앨범 | 바탕화면 전체를 저장소로 만든다 → 폴더 하나에만 · 상위에 이미 있는지 먼저 확인 |
| **커밋(commit)** | 그 시점의 상태를 이유와 함께 남긴 기록 | 게임의 세이브 포인트 | 맡기기 전에 커밋하지 않아 돌아갈 곳이 없다 |
| **diff** | 두 시점 사이에 바뀐 줄만 뽑은 것 | 빨간펜 교정 | 요약만 읽고 뜻밖의 파일을 놓친다 → [diff-review-check](../checklists/diff-review-check.md) |
| **커밋 메시지** | 무엇을 왜 바꿨는지 한 줄 — 나중의 내가 읽는 글 | 개정 이력의 비고란 | "수정"이라고만 적어 석 달 뒤 이유를 모른다 |
| **작성자(이름 · 이메일)** | 커밋마다 기록되는 만든 사람 — 한 번 기록되면 그 커밋에서는 고치지 않음 | 서명 | 실제 이메일 · 컴퓨터 이름이 공개된다 → no-reply 주소로 먼저 설정 |
| **.gitignore** | 저장소에 넣지 않을 파일 목록 | 앨범에 넣지 않을 것의 목록 | 이미 커밋한 파일은 목록에 적어도 이력에 남는다 → 첫 커밋 전에 |
| **브랜치(branch)** | 원본은 두고 시험판을 만드는 갈래 | — | 원본 위에서 바로 실험한다 |
| **revert** | 지난 변경을 거꾸로 적용한 새 커밋 — 지난 커밋을 지우지 않음 | 정정 공고 | 이력을 지우는 reset을 써서 기록이 사라진다 |
| **GitHub** | 저장소를 올려 함께 보는 곳 — Git과 다른 것 | 공유 서재 | 올리기 전 보안 점검을 건너뛴다 |
| **푸시(push) · 풀(pull)** | 내 저장소와 GitHub의 저장소를 맞추기 | 업로드 · 내려받기 | 점검 전에 올린다 — 올라간 것은 회수가 어렵다 |
| **풀 리퀘스트(pull request)** | 바꾼 것을 합쳐 달라는 제안 — 바뀐 줄 옆에 의견이 달림 | 기안 → 검토 → 결재 | 문서 전체가 아니라 바뀐 줄을 놓고 검토하는 것을 모른다 |
