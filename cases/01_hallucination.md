# 01 · 환각 — 없는 논문 · 법령 · 수치를 그럴듯하게 만든다

> 한 줄: 모델은 지식을 꺼내는 것이 아니라 가장 그럴듯한 다음 조각을 고른다. 그래서 없는 것도 있는 것처럼, 틀려도 유창하게 쓴다.

## 증상 — 겉으로 보이는 모습

- 저자 · 연도 · 제목 · 학술지까지 갖춘 참고문헌인데 검색하면 **없다**
- 법령 이름과 조문 번호가 붙어 있는데 그 조문은 **다른 내용**이거나, 그런 법이 없다
- 통계 수치가 소수점 첫째 자리까지 나오는데 출처 문서에 **그 수치가 없다**
- 물어보면 "확인했습니다"라고 답한다 — **되묻기는 소용이 없다**
- 틀린 조각이 맞는 조각 사이에 끼어 있다 — 기관 이름은 실재, 보고서 제목은 실재, 그 안의 수치만 다른 보고서 것

## 실제 모습 — 가상 예시

이 저장소의 [raw/예시_AI답변_01_정책브리프.md](../raw/예시_AI답변_01_정책브리프.md) 7행:

> 2025년 기준 전국 소규모 사업장의 63.4%가 디지털 도구를 전혀 쓰지 않고 있다(가상통계원, 2025).

기관도 수치도 가상인데 문장은 완성형이다. 9행의 「소규모사업장디지털지원법」 제12조도 같은 모양 — 법령명 · 조문 번호 · 지원 금액이 다 붙어 있어서 **더 그럴듯하다**. 검토표([out/검토표_예시01_정책브리프.md](../out/검토표_예시01_정책브리프.md))에서는 이런 행을 〔확인 못 함〕으로 적었다. 실제 자료였다면 원문을 열어 쪽을 적는다.

가상 시나리오 하나 더 — 투고 직전 참고문헌 10건을 하나씩 검색해 보니 3건이 존재하지 않는 논문이었다. 저자 이름은 그 분야의 실제 연구자, 학술지도 실재, 제목만 "그 저자가 썼을 법한" 문장이었다.

## 왜 생기나 — 원리

- **다음 토큰 예측** — 모델은 "이 자리에 올 법한 조각"을 고른다. 참고문헌 · 법령 조문 · 통계 문장은 형식이 매우 규칙적이어서, 실재 여부와 무관하게 '그럴듯한 참고문헌'을 만드는 일을 잘한다.
- **맞는 조각을 잘못 이어 붙임** — 드문 사실일수록 조각이 섞인다. 기관은 맞고 수치는 다른 해의 것, 저자는 맞고 제목은 다른 논문의 것.
- **모른다고 말하도록 평가되지 않았다** — 시험에서 빈칸보다 추측이 점수가 높듯, 모델도 "모르겠다"보다 그럴듯한 답을 내놓는 쪽으로 다듬어져 왔다(Kalai et al., 2025).
- **"확실해?"에도 또 다음 조각을 고를 뿐** — 원문을 다시 읽는 것이 아니다. 되묻기는 확인이 아니라 두 번째 추측 요청이다.
- **학습 시점 이후를 모른다** — 지난해 법령 · 올해 통계는 애초에 없다. 그 자리를 옛 것이나 추측으로 채운다.

## 어떻게 잡나 — 확인 순서

1. **실재** — 제목 · 저자 · 연도로 검색한다. 논문은 DOI, 법령은 법령 번호와 시행일, 보도자료는 발행 번호까지. 하나라도 안 맞으면 〔확인 못 함〕.
2. **귀속** — 실재하더라도 **그 문서의 그 쪽에 그 문장 · 그 수치가 있는가**를 본다. 주소가 열려도 내용이 없을 수 있다([02](02_citation-failure.md)).
3. **표기** — 연도 · 쪽 · 판 · 개정 여부.
4. **범위** — 내가 준 자료 안에서만 답하라고 했는가. 밖에서 끌어온 것은 전부 확인 대상이다.
5. **빠르게 시작하려면** — 검토표에서 유형이 '출처'인 행부터 연다. 출처 없이 수치만 있는 행('수치')은 **출처부터 요구**한다.

## 예방 규칙 — 요청문 · 규칙 파일 · 장치

- **요청문에 범위를 적는다** — "근거는 raw/의 파일 안에서만. 없는 것은 지어내지 말고 〔확인 필요〕로 남겨라."
- **규칙 파일(CLAUDE.md) 한 줄** — "수치 · 인용 · 법령 조문은 원문을 열어 쪽수와 함께 적는다. 열지 못한 것은 〔확인 못 함〕."
- **검증 가능한 일로 바꾼다** — "출처 10건 → 실재 10건 · 귀속 10건"처럼 숫자로. "정확하게"는 판정할 수 없다.
- **집필과 검수를 나눈다** — 검수는 새 세션에서, 쓴 쪽이 아닌 다른 눈으로. 같은 창의 자기 평가는 "됐다"로 기운다([06](06_completion-claim.md)).
- **원문 열람을 완료 정의에 넣는다** — "인용 전수 열람 · 귀속 오류 0"이 아니면 끝난 것이 아니다.
- **최신 법령 · 통계는 모델에게 묻지 않는다** — 공식 API · 원문 조회 결과를 자료로 준다.

## 되풀이되면 — 결과물이 아니라 장치를 고친다

같은 지적을 두 번 하게 되면 고칠 곳은 답변이 아니다. 요청문의 범위 · 규칙 파일의 한 줄 · 검수 단계의 유무를 고친다. 결과물을 고치면 이번 한 번만 나아지고, 장치를 고치면 다음부터 계속 나아진다.

## 부록 · 가상 사례 모음 — C-001 ~ C-016 (16건)

> 아래는 2026-10-10 리서치 컬렉션(ai-failure-patterns-research.pdf와 함께 받은 번들)에서 결합한 짧은 가상 예시다. 실제 인물 · 기관 · 고객과 무관하며, 번호(C-###)는 인용할 때 쓰는 고정 번호다. 각 예시는 상황 · 증상 · 원인 · 확인 방법 · 예방 규칙 다섯 줄로 되어 있고, 위의 본문보다 짧은 대신 장면이 다양하다.

#### C-001 · 존재하지 않는 논문 인용
- 상황(가상): 대학원생이 문헌 검토 중 "○○ 분야 최신 연구 3편을 요약해줘"라고 요청.
- 증상: 저널명·연도·저자가 그럴듯한 논문 3편이 제시됐지만 실제로 존재하지 않음.
- 원인: 인용 형식은 생성 가능하나 실제 문헌 색인과 대조하지 않음.
- 확인 방법: DOI·저널명으로 학술 DB에서 검색.
- 예방 규칙: 인용을 받으면 반드시 원문을 열어 존재와 내용을 확인한다.

#### C-002 · 없는 법조문 조항 번호
- 상황(가상): 정책 보고서 작성 중 "관련 법 제○조의 내용을 정리해줘"라고 요청.
- 증상: 존재하지 않는 조항 번호와 그럴듯한 조문 내용이 제시됨.
- 원인: 법령 구조를 추론해 생성, 최신 법령 확인 없음.
- 확인 방법: 국가법령정보센터 등 공식 원문에서 조항 확인.
- 예방 규칙: 법조문은 공식 원문에서만 인용한다.

#### C-003 · 그럴듯한 가짜 통계
- 상황(가상): 발표자료용으로 "○○ 시장 규모 통계를 찾아줘"라고 요청.
- 증상: 출처 없이 소수점까지 붙은 구체적 수치가 제시됨.
- 원인: 정확한 수치 대신 그럴듯한 값을 생성.
- 확인 방법: 원 보고서·통계청 자료에서 수치 대조.
- 예방 규칙: 출처 없는 수치는 사용하지 않는다.

#### C-004 · 존재하지 않는 제품 사양
- 상황(가상): 구매 검토 중 "A사 노트북 B모델 사양"을 물음.
- 증상: 실제로 없는 모델명과 스펙이 자연스럽게 제시됨.
- 원인: 제품 DB 조회 없이 유사 모델을 조합.
- 확인 방법: 제조사 공식 페이지 확인.
- 예방 규칙: 제품 사양은 제조사 공식 자료로 확인한다.

#### C-005 · 가짜 인물 경력
- 상황(가상): 행사 소개문을 쓰며 "이 분야 대표 연구자 소개"를 요청.
- 증상: 실존하지 않는 인물의 소속·업적이 구체적으로 서술됨.
- 원인: 실존 인물 확인 없이 프로필을 생성.
- 확인 방법: 소속 기관·공개 프로필로 교차 확인.
- 예방 규칙: 실명 인물 정보는 1차 출처로 확인한다.

#### C-006 · 없는 표준·규격 번호
- 상황(가상): 품질 문서에 "적용 표준"을 기입하려 함.
- 증상: 존재하지 않는 ISO/IEC 번호와 제목이 제시됨.
- 원인: 표준 목록 조회 없이 번호 체계를 추론.
- 확인 방법: 표준화 기구 공식 카탈로그 확인.
- 예방 규칙: 표준 번호는 표준기구 원문에서 확인한다.

#### C-007 · 시점이 뒤섞인 사건 서술
- 상황(가상): 최근 사건을 요약해 달라고 요청.
- 증상: 실제로는 없었던 사건, 또는 순서가 뒤바뀐 서술이 확신 있게 나옴.
- 원인: 최신 정보 접근 없이 기억을 조합.
- 확인 방법: 언론·공식 발표로 날짜 확인.
- 예방 규칙: 시점이 중요한 사안은 최신 출처로 재확인한다.

#### C-008 · 존재하지 않는 기관 보고서
- 상황(가상): 정책 근거로 "○○부 보고서 발췌"를 요청.
- 증상: 문서명·발간연도가 구체적이나 실제 발간 이력이 없음.
- 원인: 기관명과 문서명을 조합해 생성.
- 확인 방법: 기관 홈페이지 발간물 목록 확인.
- 예방 규칙: 보고서는 원문 파일로 확인한다.

#### C-009 · 그럴듯한 오류 코드·에러 메시지
- 상황(가상): 프로그램 오류 해결 중 "이 증상의 원인"을 물음.
- 증상: 실제로 발생하지 않는 오류 코드와 원인 설명이 제시됨.
- 원인: 로그를 보지 않고 일반 패턴으로 답변.
- 확인 방법: 실제 로그·문서의 코드와 대조.
- 예방 규칙: 오류는 원문 로그를 근거로만 진단한다.

#### C-010 · 없는 지도·주소 정보
- 상황(가상): 답사 계획 중 "○○ 근처 시설 주소"를 요청.
- 증상: 존재하지 않는 주소·시설명이 제시됨.
- 원인: 지도 데이터 조회 없이 추정.
- 확인 방법: 지도 서비스에서 실제 검색.
- 예방 규칙: 주소·위치는 지도에서 직접 확인한다.

#### C-011 · 가짜 인용문(명언)
- 상황(가상): 발표 도입부용 명언을 요청.
- 증상: 실존 인물에게 하지 않은 말이 인용문으로 제시됨.
- 원인: 유명 문장을 재조합.
- 확인 방법: 원 발언 출처 확인.
- 예방 규칙: 인용문은 원 출처가 있을 때만 쓴다.

#### C-012 · 존재하지 않는 데이터셋
- 상황(가상): 분석 과제에서 "공개 데이터셋을 추천해줘"라고 요청.
- 증상: 이름과 링크가 그럴듯하나 실제로 없는 데이터셋.
- 원인: 데이터 저장소 조회 없이 생성.
- 확인 방법: 데이터 저장소에서 검색해 실존 확인.
- 예방 규칙: 데이터셋은 실제 URL로 접속해 확인한다.

#### C-013 · 앞뒤 모순되는 자기 서술
- 상황(가상): 긴 대화에서 같은 질문을 여러 번 함.
- 증상: 앞서 말한 수치·조건과 뒤의 답이 서로 모순됨.
- 원인: 컨텍스트 내 일관성 유지 실패.
- 확인 방법: 대화 로그에서 같은 항목끼리 비교.
- 예방 규칙: 핵심 수치는 별도 표로 고정해 대조한다.

#### C-014 · 없는 업데이트·패치
- 상황(가상): 소프트웨어 이슈 해결 중 "최신 버전"을 물음.
- 증상: 출시되지 않은 버전 번호와 변경 사항이 제시됨.
- 원인: 버전 규칙을 추론해 생성.
- 확인 방법: 공식 릴리스 노트 확인.
- 예방 규칙: 버전·패치는 공식 릴리스 페이지로 확인한다.

#### C-015 · 가짜 계약·약관 조항
- 상황(가상): 계약서 초안 검토 중 "표준 조항"을 요청.
- 증상: 실제 표준과 다른, 존재하지 않는 조항이 일반 관행처럼 제시됨.
- 원인: 관행을 추정해 서술.
- 확인 방법: 실제 계약·법률 자문으로 확인.
- 예방 규칙: 계약 조항은 전문가 검토를 거친다.

#### C-016 · 그럴듯한 화학·의약 정보
- 상황(가상): 성분 정보를 요약해 달라고 요청.
- 증상: 잘못된 성분·용량 정보가 확신 있게 제시됨.
- 원인: 전문 데이터베이스 대조 없이 생성.
- 확인 방법: 공인 데이터베이스·전문가 확인.
- 예방 규칙: 의약·화학 정보는 전문 출처로만 인용하고 그대로 사용하지 않는다.
