# 03 · 맥락 오류 — 다른 나라 · 지난 시점 · 다른 대상 · 다른 단위로 답한다

> 한 줄: 모델이 아는 것은 컨텍스트에 들어온 것뿐이다. 내가 말하지 않은 나라 · 날짜 · 대상 · 단위는 가장 흔한 기본값으로 채워진다.

## 증상 — 겉으로 보이는 모습

- 한국 제도를 물었는데 **다른 나라 기준**으로 설명한다(학습 데이터에 많은 쪽이 기본값)
- **개정 전 규정**을 현행처럼 답한다 — 법 · 지침 · 요금 · 마감일
- **대상 집단이 바뀐다** — 전체 평균을 물었는데 특정 집단 수치, 청년 정책을 물었는데 전체 통계
- **단위 · 통화가 어긋난다** — 해외 통화 환산이 10배 틀린 채 판단이 이어진다 · 천 명과 명 · 백만 원과 억 원
- **"최근" · "현재"가 모델의 학습 시점**이다 — 올해라고 썼지만 재작년 기준
- 질문의 전제를 그대로 받아 **틀린 전제 위에서 유창하게** 답한다(아첨)

## 실제 모습 — 가상 예시

[raw/예시_AI답변_02_통계요약.md](../raw/예시_AI답변_02_통계요약.md)는 **2026년 8월** 실적 표인데, AI 요약 첫 줄은 이렇게 시작한다:

> 2026년 9월 기준 지원사업 신청은 총 4,560건…

수치는 표와 같다. 시점만 한 달 밀렸다. 이 요약이 보고서에 실리면 9월 수치로 읽힌다. 검토표의 '시점' 유형은 이것을 잡기 위한 것이다.

[raw/예시_AI답변_01_정책브리프.md](../raw/예시_AI답변_01_정책브리프.md) 26행의 "선진국 평균(28.1%)"도 같은 종류 — 어느 나라 묶음인지 · 어느 해인지 · 같은 정의인지가 없다.

## 왜 생기나 — 원리

- **컨텍스트에 없는 것은 없는 것** — 나라 · 시점 · 대상 · 단위를 적지 않으면 모델은 묻지 않고 **학습 데이터에서 가장 흔한 값**으로 채운다.
- **학습 시점 이후를 모른다** — 지난해 개정, 올해 통계는 애초에 없다. 그 자리를 옛 값으로 메운다.
- **아첨(동조)** — 질문에 담긴 전제("…가 늘었다는데")를 바로잡기보다 따라간다. 내 결론을 먼저 말하면 그 결론에 맞춘다.
- **단위는 숫자와 따로 다닌다** — 숫자 조각과 단위 조각이 각각 그럴듯하게 선택된다. 환산은 계산이 아니라 예측이다([04](04_number-failure.md)).

## 어떻게 잡나 — 확인 순서

네 가지를 문장마다 묻는다 — **국가 · 기준일 · 대상 · 단위**.

1. **국가 · 지역** — 어느 나라 · 어느 기관의 제도인가. 법령 이름이 한국 것인가.
2. **기준일** — 자료의 기준 시점과 문장의 시점이 같은가. "현재"는 언제인가. 개정 · 시행일은.
3. **대상** — 분모가 무엇인가. 전체인가 일부인가. 정의가 원자료와 같은가.
4. **단위 · 통화** — 천 · 만 · 억, 원 · 달러 · 환율 기준일, %와 %p.
5. **전제** — 내가 질문에 넣은 전제를 모델이 그대로 받았는가. 전제부터 확인한다.

## 예방 규칙 — 요청문 · 규칙 파일 · 장치

- **요청문에 네 가지를 적는다** — "대한민국 · 2026년 10월 기준 · 소규모 사업장(상시 근로자 5인 미만) · 단위는 백만 원." 적지 않은 것은 추측으로 채워진다.
- **최신 법령 · 통계는 자료로 준다** — 모델에게 "현행"을 묻지 않는다. 공식 원문 · API 조회 결과를 raw/에 넣고 "이 안에서만".
- **내 결론을 먼저 말하지 않는다** — "A가 늘었지?" 대신 "A의 추이를 원자료 표에서 읽어라."
- **규칙 파일 한 줄** — "모든 수치에는 기준일과 단위를 붙인다. 원자료에 없는 기준일은 〔확인 필요〕."
- **출력 형식에 칸을 둔다** — 표에 '기준일' · '단위' 열을 강제하면 비어 있는 것이 보인다.

## 되풀이되면 — 결과물이 아니라 장치를 고친다

같은 나라 · 같은 시점 오류가 두 번째 나오면, 요청문에 매번 적을 것이 아니라 규칙 파일(항상 읽히는 곳)에 한 줄로 올린다. 기준일 · 단위 열이 있는 출력 양식을 만들어 두면 빈칸이 스스로 드러난다.

## 부록 · 가상 사례 모음 — C-029 ~ C-040 (12건)

> 아래는 2026-10-10 리서치 컬렉션(ai-failure-patterns-research.pdf와 함께 받은 번들)에서 결합한 짧은 가상 예시다. 실제 인물 · 기관 · 고객과 무관하며, 번호(C-###)는 인용할 때 쓰는 고정 번호다. 각 예시는 상황 · 증상 · 원인 · 확인 방법 · 예방 규칙 다섯 줄로 되어 있고, 위의 본문보다 짧은 대신 장면이 다양하다.

#### C-029 · 제도를 다른 나라 기준으로 설명
- 상황(가상): 국내 제도를 설명해 달라고 요청.
- 증상: 다른 나라의 유사 제도를 국내 제도처럼 설명.
- 원인: 국가 맥락 미지정, 유사 제도 혼합.
- 확인 방법: 해당 국가 공식 자료로 확인.
- 예방 규칙: 국가·제도를 프롬프트에 명시한다.

#### C-030 · 시점 불일치(개정 전 기준)
- 상황(가상): 현행 규정을 확인하려 함.
- 증상: 이미 개정된 예전 기준으로 안내.
- 원인: 최신성 확인 없이 답변.
- 확인 방법: 최신 원문·시행일 확인.
- 예방 규칙: "언제 기준인지"를 명시하고 최신 출처로 확인한다.

#### C-031 · 사용자 의도와 다른 산업 맥락
- 상황(가상): 규제를 물으며 특정 업종을 염두에 둠.
- 증상: 다른 업종 기준의 답변이 일반론으로 제시됨.
- 원인: 업종 미지정.
- 확인 방법: 답변이 업종 전제와 맞는지 확인.
- 예방 규칙: 업종·규모·적용 범위를 먼저 밝힌다.

#### C-032 · 독자 수준 불일치
- 상황(가상): 초등학생용 설명을 요청.
- 증상: 전문용어가 그대로 나와 대상이 이해 못 하는 수준.
- 원인: 독자 수준 미지정.
- 확인 방법: 대상 독자가 읽어 이해하는지 확인.
- 예방 규칙: 독자(연령·배경)를 명시하고 예시를 요구한다.

#### C-033 · 반말·존대 맥락
- 상황(가상): 격식 있는 공문 작성을 요청.
- 증상: 지나치게 캐주얼한 어투가 섞임.
- 원인: 톤 미지정.
- 확인 방법: 문서 성격에 맞는지 검토.
- 예방 규칙: 문서 목적·수신자·톤을 명시한다.

#### C-034 · 지역·단위 체계 무시
- 상황(가상): 국내 문서에 수치를 넣으려 함.
- 증상: 다른 국가 단위(마일·화씨 등)가 그대로 사용됨.
- 원인: 단위 체계 미지정.
- 확인 방법: 단위 표기 확인.
- 예방 규칙: 단위·통화·표준시를 명시한다.

#### C-035 · 조직 규정 무시
- 상황(가상): 조직 내 보고 형식을 요청.
- 증상: 일반 관행과 조직 고유 규정이 충돌.
- 원인: 조직 내부 규칙 미제공.
- 확인 방법: 내부 규정과 대조.
- 예방 규칙: 내부 규정을 별도로 제공한다.

#### C-036 · 역사적 사건의 시기 혼동
- 상황(가상): 특정 사건의 배경을 요약해 달라고 요청.
- 증상: 사건의 순서·시기가 뒤섞임.
- 원인: 연표 미확인.
- 확인 방법: 연표·공식 기록 확인.
- 예방 규칙: 시점이 중요한 서술은 연표로 대조한다.

#### C-037 · 인과관계 과잉 단정
- 상황(가상): 두 사건의 관계를 물음.
- 증상: 상관관계를 인과로 단정.
- 원인: 맥락·변수 통제 미고려.
- 확인 방법: 원 연구의 표현(상관/인과) 확인.
- 예방 규칙: 인과 표현은 근거 수준에 맞춘다.

#### C-038 · 문화적 맥락 누락
- 상황(가상): 지역 행사 홍보문을 작성.
- 증상: 문화적으로 부적절하거나 어색한 표현.
- 원인: 문화 맥락 미고려.
- 확인 방법: 현지 독자 검토.
- 예방 규칙: 문화·언어 뉘앙스를 명시하고 검토를 받는다.

#### C-039 · 학문 분야별 용어 혼동
- 상황(가상): 특정 학문 분야 용어를 사용.
- 증상: 다른 분야 의미의 용어가 사용됨.
- 원인: 분야 특정 없이 일반 정의 적용.
- 확인 방법: 해당 분야 교재·사전 확인.
- 예방 규칙: 분야와 용어 정의를 명시한다.

#### C-040 · 권한 수준 무시
- 상황(가상): 결재가 필요한 업무를 처리.
- 증상: 승인 절차를 건너뛴 결과물이 제안됨.
- 원인: 조직 권한 체계 미제공.
- 확인 방법: 권한·결재 절차 확인.
- 예방 규칙: 권한 범위와 승인 절차를 명시한다.
