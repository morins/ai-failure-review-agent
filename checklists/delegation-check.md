# 맡기기 전 — 요청문 · 커밋 · 되돌릴 수 있는가

> 맡기는 범위는 되돌릴 수 있고 내가 검토할 수 있는 데까지. 오늘의 한 줄 — **맡기기 전에 커밋, 끝나면 diff.**

## 0 이 일을 맡겨도 되는가

- [ ] **검증할 수 있는 일인가** — 표 옮기기(원자료와 칸별 대조) · 인용 확인(원문과 대조) · 파일 정리(개수 · 이름 일치)는 맡기기 쉽다. "설득력 있게" · "문장이 좋은가" · "무엇이 중요한가"는 채점 기준이 없다 — **기준부터 만든다**
- [ ] **되돌릴 수 있는가** — 원본은 잠그고(권한 deny) 사본에서 일하게 한다. 되돌릴 수 없는 일(발송 · 게시 · 삭제)은 사람이 직접
- [ ] **내가 검토할 수 있는 크기인가** — 15분 안에 diff를 읽을 수 있는 크기로. 바뀐 것이 너무 많아 읽을 수 없으면 맡긴 일이 컸다는 신호
- [ ] **직접 할 것도 설계 항목이다** — 이해가 필요한 일(새로 배우는 것 · 판단이 쌓이는 것)은 통째로 넘기지 않는다. 넘긴 만큼 이해가 남지 않는다

## 1 요청문 다섯 칸

| 칸 | 적을 것 | 빠지면 |
|---|---|---|
| **목적과 이유** | 무엇을 위해 · 왜 지금 | 엉뚱한 방향으로 최적화 |
| **할 일** | 내 폴더의 파일 이름으로 | "이 폴더 자료"가 무엇인지 추측 |
| **권한의 한계** | 고쳐도 되는 것 · 고치면 안 되는 것 · 하면 안 되는 명령(커밋 · 삭제 · 외부 전송) · "저장할지는 내가 본 뒤에" | **금지가 가장 자주 빠지고 사고는 거기서 난다** |
| **완료의 모습** | 무엇이 어떤 상태면 끝인지 — 눈으로 확인할 수 있게 · 숫자로 | "다 됐다"를 검증할 수 없음 |
| **필요한 산출물** | 남길 파일의 이름과 위치 · 무엇을 바꿨는지 세 줄 요약 | 결과가 대화 속에만 남음 |

양식:

```text
아래 일을 맡길게. 시작하기 전에 네가 이해한 내용을 세 줄로 먼저 말해줘.

목적과 이유: (무엇을 위해 이 일을 하는지, 왜 지금 필요한지)
할 일: (맡길 일 — 내 폴더의 파일 이름으로)
권한의 한계: 고쳐도 되는 것은 (파일 또는 폴더 이름)뿐이야. (원본 폴더)와 (규칙 파일)은 고치지 마. 파일을 지우지 마. 커밋이나 되돌리기 같은 git 명령은 실행하지 마. 저장할지는 내가 바뀐 것을 본 뒤에 정할게.
완료의 모습: (무엇이 어떤 상태면 끝난 것인지 — 눈으로 확인할 수 있게)
필요한 산출물: (남길 파일의 이름과 위치), 그리고 무엇을 바꿨는지 세 줄 요약
```

## 2 맡기기 직전

- [ ] **예상을 먼저 적는다** — 직접 하면 걸리는 시간 · 한 번에 될 것 같은 정도(열 번 중 몇 번) · 요청과 확인에 드는 시간. 끝난 뒤 실제와 나란히 놓는다
- [ ] **커밋한다** — "맡기기 전 저장". 커밋하지 않은 변경이 남아 있지 않은지 확인. 되돌아갈 지점이 생긴다
- [ ] **규칙이 파일에 있는가** — 이번 일에 꼭 지켜야 할 규칙이 대화가 아니라 규칙 파일(CLAUDE.md)에 있는지. 새 대화를 열면 그 파일이 처음부터 읽힌다
- [ ] **권한 설정** — 원본 폴더 편집 deny · 삭제 명령 deny · 외부 전송 ask. 되돌릴 수 있는 범위까지만 허용
- [ ] **시작 전 세 줄** — 에이전트가 말한 "이해한 내용"이 내 뜻과 같은지. 다르면 시작 전에 바로잡는다 — 방향을 가장 싸게 바꿀 수 있는 자리

## 3 맡기는 동안

- [ ] 권한 창이 뜨면 **명령을 읽고** 내가 적은 권한의 한계와 같은 종류인지 대조한 뒤 허용
- [ ] 원본 폴더를 고치려 하면 거부 → "out/에만 써줘"
- [ ] 같은 오류가 반복되면 오류 문구를 그대로 붙여 "고치기 전에 원인부터" · 두 번 넘으면 새 대화
