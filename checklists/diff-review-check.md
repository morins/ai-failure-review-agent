# 끝난 뒤 diff — 요약 말고 바뀐 줄부터

> 에이전트의 요약이 아니라 diff와 파일 목록에서 내가 읽은 것으로 판정한다. 잘 읽히는 요약 뒤에 뜻밖의 파일이 있다.

## 1 목록부터

- [ ] **고친 파일 · 새로 생긴 파일 · 지워진 파일**로 나눈 목록을 먼저 받는다 — 새로 생긴 파일은 diff에 나오지 않고 목록에만 나온다
- [ ] **권한의 한계 밖**의 파일이 있는가 — 시키지 않은 변경이 되돌릴 첫 후보
- [ ] 파일 수가 예상보다 많으면 멈추고 묻는다 — "왜 이 파일을 고쳤는지 근거가 되는 줄을 보여줘"

요청문:

```text
직전 저장점(커밋)과 지금 작업 폴더의 차이를 보여 줘. 먼저 바뀐 파일 목록을 수정 · 신규 · 삭제로 나누고, 수정 파일은 바뀐 줄로, 신규 파일은 내용 요약으로. 허용 범위 밖 파일이 있으면 맨 위에 따로 적어 줘. 저장(커밋)은 하지 마.
```

## 2 diff 읽는 법

```
diff --git a/plan.md b/plan.md        파일 이름 — 여기만 읽는다
index 65fa310..80f0e59 100644         내부 식별값 — 넘어간다
--- a/plan.md                         넘어간다
+++ b/plan.md                         넘어간다
@@ -12,7 +12,7 @@                     12행 근처가 바뀌었다는 뜻 — 위치만
 - [x] 6. 굳히기                      기호 없음 — 바뀌지 않은 앞뒤 문맥
-- [ ] 7. 예시02로 한 번 더 돌리기     빨강 -  빠진 줄 — 읽는다
+- [x] 7. 예시02로 한 번 더 돌리기     초록 +  들어간 줄 — 읽는다
```

- [ ] 읽을 곳은 **-로 시작하는 줄과 +로 시작하는 줄**. 나머지 머리글은 위치 정보다
- [ ] 한 줄을 고치면 빨강 하나와 초록 하나가 짝으로 나온다. 의도한 줄만 바뀌었는가
- [ ] 마지막 줄에 줄바꿈이 없었다는 안내(`\ No newline at end of file`)는 오류가 아니다
- [ ] 한글 · 워드 · PDF 파일은 "바뀌었다"는 한 줄만 나온다 — 비교가 필요한 원고는 .md로 둔다

## 3 완료의 모습과 대조

- [ ] 내가 적은 **완료의 모습**을 항목마다 통과 · 미통과로 — 에이전트의 "다 했다"가 아니라 내 눈으로
- [ ] 결과 파일을 **직접 연다** · 돌려 본다 · 센다
- [ ] 검증 스크립트가 있으면 **출력을 그대로** 본다(요약 말고)
- [ ] 규칙 파일에 더한 줄이 있다면 **이번 결과에서 지켜졌는가** — 규칙을 외워 말하게 하지 않고 일을 시킨 결과로 확인
- [ ] "확인했다"고 적힌 문장마다 **무엇을 열어 대조했는지** — 근거가 없으면 〔확인 못 함〕으로 고쳐 적는다

## 4 판정 — 되돌리기 세 방식

| 명령 | 하는 일 | 남는 것 | 이 체크리스트에서 |
|---|---|---|---|
| revert | 지난 변경을 거꾸로 적용한 새 저장본을 만든다 | 무엇을 왜 되돌렸는지가 이력에 남는다 | **기본** |
| restore | 저장하지 않은 수정을 버린다 | 버린 것은 복구할 수 없다 | 꼭 필요할 때만 |
| reset | 저장본 자체를 지운다 | 이력이 사라진다 | **쓰지 않는다** |

- **전부 받아들일 때** — 받아들인 이유가 보이는 메시지로 저장한다
- **일부만 받아들일 때** — 받아들일 파일만 먼저 저장하고, 나머지는 "받아들이지 않은 변경"으로 따로 저장한 뒤 revert로 되돌린다
- **전부 되돌릴 때** — 결과 전체를 "받아들이지 않음"으로 저장한 뒤 revert한다. 버릴 변경도 먼저 저장하는 이유는 에이전트가 무엇을 했는지의 기록이 사라지지 않게 하기 위해서다

## 5 기록

- [ ] 바꾼 것(파일 이름과 내용) · 받아들인 것과 이유 · 되돌린 것과 이유(없으면 "없음"과 근거)
- [ ] 범위 밖 변경이 있었나 · 완료의 모습이 실제로 되었나(내 눈으로 확인한 방법)
- [ ] **다음에 맡길 때 요청문에서 고칠 한 줄** — 같은 지적을 두 번 하게 되면 고칠 곳은 결과물이 아니라 요청문 · 규칙 파일
