# 05 · 지시 실패 — 빈칸을 그럴듯한 기본값으로 메운다

> 한 줄: 문장이 틀린 게 아니라 빈칸이 많은 것이다. 빈칸은 추측으로 메워지고, 무엇을 기준으로 했는지는 아무 데도 남지 않는다.

## 증상 — 겉으로 보이는 모습

- "알아서 잘" 했더니 **내가 정한 적 없는 분류 체계**로 300건이 분류되어 있다
- 빈 셀은 0으로, 형식은 모델이 좋아하는 형식으로, 끝나는 시점은 "대충 됐을 때"로 정해져 있다
- **금지를 적지 않은 것**이 사고가 된다 — 원본 파일을 고쳐 놓음 · 외부로 내보냄 · 지우고 다시 만듦
- "좋게 써 줘"의 결과가 그럴듯하지만 **내 기준이 아니다** — 독자 · 톤 · 분량이 모두 기본값
- 한 번에 너무 많이 시켜서 **뒤쪽 요구가 흐려졌다**
- 같은 지시를 다음 사람이 해도 **같은 결과가 나오지 않는다** — 지시가 파일이 아니라 머릿속에 있어서

## 실제 모습 — 가상 예시

> 이 폴더의 설문 응답 400건을 주제별로 묶어 줘. 적당히 보기 좋게.

이 한 줄에서 비어 있는 것 — 주제 목록(몇 개 · 이름) · 한 응답이 두 주제에 걸칠 때의 규칙 · 빈 응답의 처리 · 결과 파일 형식 · "분류 못 함"의 허용 비율 · 원본을 건드려도 되는지. 여섯 빈칸이 전부 모델의 기본값으로 채워진다. 결과는 그럴듯하고, 검수는 불가능하다 — "적당히"는 판정할 수 없기 때문이다.

빈칸을 채운 지시는 이런 모양이다:

> raw/응답.csv의 400건을 raw/주제표.md의 9개 주제로 묶어 out/주제별_v1.csv에 써라. 두 주제에 걸치면 첫째 주제에 넣고 '복수' 열에 둘째를 적어라. 주제를 정할 수 없으면 '미분류'로 두고, 미분류가 5%를 넘으면 멈추고 보고해라. raw/는 수정하지 마라.

이제 "미분류 5% 미만"이라는 **숫자가 루프를 멈춘다**.

## 왜 생기나 — 원리

- **되묻기보다 채우기** — 모델은 모르는 것을 묻기보다 가장 흔한 값으로 채우도록 다듬어져 있다. 묻는 쪽이 덜 유창해 보이기 때문이다.
- **빈칸은 가장 흔한 값으로** — 분류 체계 · 파일 형식 · 톤은 학습 데이터에서 제일 흔한 것이 기본값이다. 내 조직의 기준은 거기 없다.
- **금지는 제일 자주 빠진다** — 사람끼리는 "원본 건드리지 마"를 말하지 않아도 안다. 모델에게는 적지 않은 금지가 없는 금지다.
- **아첨** — 내가 결론을 먼저 말하면 그 결론에 맞춘다.
- **긴 지시의 뒤쪽은 약해진다** — 한 번에 열 가지를 시키면 뒤의 세 가지는 흐려진다.

## 어떻게 잡나 — 확인 순서

결과물에서 **"내가 정한 적 없는 선택"**을 찾는다.

1. **분류 · 체계** — 어떤 범주 · 어떤 순서 · 어떤 이름을 썼는가. 내가 준 것인가.
2. **형식** — 파일 형식 · 표 모양 · 단위 · 날짜 표기. 내가 정했는가.
3. **범위** — 무엇을 포함하고 무엇을 뺐는가. 뺀 기준은.
4. **끝** — 언제 끝났다고 봤는가. 완료의 모습을 내가 적었는가.
5. **금지** — 원본 · 외부 전송 · 삭제 · 설치 가운데 일어난 것이 있는가. diff로 범위 밖 변경을 본다([checklists/diff-review-check.md](../checklists/diff-review-check.md)).
6. **시작 전 확인** — 실행 전에 받은 목표 · 범위 · 완료 조건 요약이 내 뜻과 같았는가.

## 예방 규칙 — 요청문 · 규칙 파일 · 장치

지시의 품질은 문장력이 아니라 **빠진 조건의 수**로 정해진다. 다섯 칸을 채운다:

| 칸 | 적을 것 | 예 |
|---|---|---|
| 목적과 이유 | 무엇을 위해 · 왜 지금 | "보고서 검토 부담을 줄이려고 · 이번 주 제출" |
| 할 일 | 내 폴더의 파일 이름으로 | "raw/예시_02.md로 out/검토표_예시02.md" |
| 권한의 한계 | 고쳐도 되는 것 · 고치면 안 되는 것 · 금지 명령 | "out/만 · raw/ · CLAUDE.md 금지 · 커밋 · 삭제 금지" |
| 완료의 모습 | 눈으로 확인할 수 있게 · 숫자로 | "행 수 = 주장 수 · 판정 칸 비움 · 검사 통과" |
| 필요한 산출물 | 파일 이름 · 위치 · 세 줄 요약 | "out/… + 무엇을 바꿨는지 세 줄" |

- **시작 전 요약 확인** — "실행하기 전에 네가 이해한 목표 · 범위 · 완료 조건을 각각 한 줄로 먼저 보내라." 내 뜻과 다르면 시작 전에 바로잡는다 — 방향 오류를 가장 싸게 잡는 자리.
- **계획 먼저** — 큰 일은 실행 전에 계획만 받아 본다. 품질을 높이는 장치라기보다 방향이 틀렸을 때 가장 싸게 돌아오는 장치다.
- **지시를 파일로** — 기획안(02_기획안.md) · 규칙 파일(CLAUDE.md)에 적으면 다음 대화 · 다음 사람에게도 같은 스펙이 읽힌다. 지시 파일 자체가 재현 자산이다.
- **쪼개서 숫자로** — 자료 60건을 나눠 맡기면 "한 묶음에 5건"처럼 단위를 숫자로 적는다. 안 적으면 한 번에 다 읽으려다 컨텍스트가 넘친다.

## 되풀이되면 — 결과물이 아니라 장치를 고친다

같은 종류의 빈칸이 두 번 채워지면, 그 칸은 요청문이 아니라 규칙 파일로 올린다. "매번 적어야 하는 것"은 "한 번 적어 두는 것"이 되어야 한다.

## 부록 · 가상 사례 모음 — C-053 ~ C-066 (14건)

> 아래는 2026-10-10 리서치 컬렉션(ai-failure-patterns-research.pdf와 함께 받은 번들)에서 결합한 짧은 가상 예시다. 실제 인물 · 기관 · 고객과 무관하며, 번호(C-###)는 인용할 때 쓰는 고정 번호다. 각 예시는 상황 · 증상 · 원인 · 확인 방법 · 예방 규칙 다섯 줄로 되어 있고, 위의 본문보다 짧은 대신 장면이 다양하다.

#### C-053 · 너무 추상적인 요청
- 상황(가상): "보고서 좋게 써줘"라고만 요청.
- 증상: 목적과 무관한 일반론.
- 원인: 목적·독자·기준 미지정.
- 확인 방법: 결과가 실제 요구를 채우는지 확인.
- 예방 규칙: 목적·독자·톤·형식을 지정한다.

#### C-054 · 역할만 주고 자료 없음
- 상황(가상): "전문가처럼 답해줘"만 요청.
- 증상: 그럴듯하나 근거 없는 답변.
- 원인: 입력 자료·판단 기준 미제공.
- 확인 방법: 인용·근거 유무 확인.
- 예방 규칙: 자료와 판단 기준을 함께 준다.

#### C-055 · 한 번에 너무 많이 요구
- 상황(가상): 요약·번역·표 작성·검토를 한꺼번에 요청.
- 증상: 일부 항목 누락, 품질 저하.
- 원인: 작업 범위 과다.
- 확인 방법: 각 요구가 반영됐는지 항목별 확인.
- 예방 규칙: 단계로 나눠 순차 요청한다.

#### C-056 · 검증 요청 없음
- 상황(가상): 사실 확인 없이 초안만 요청.
- 증상: 환각이 그대로 포함.
- 원인: 근거·불확실성 표시 요구 없음.
- 확인 방법: 출처·불확실 표시 확인.
- 예방 규칙: "근거·출처·불확실성"을 요구한다.

#### C-057 · 출력 형식 미지정
- 상황(가상): 표가 필요한데 문장으로 요청.
- 증상: 재사용 어려운 서술형 출력.
- 원인: 형식 미지정.
- 확인 방법: 원하는 형식인지 확인.
- 예방 규칙: 표·목차·CSV 등 형식을 지정한다.

#### C-058 · 맥락 없는 후속 질문
- 상황(가상): 새 대화에서 "그거 더 해줘"라고 요청.
- 증상: 엉뚱한 대상에 대한 답.
- 원인: 지시 대상 미명시.
- 확인 방법: 대상이 맞는지 확인.
- 예방 규칙: 후속 요청엔 대상을 다시 적는다.

#### C-059 · 상충되는 제약
- 상황(가상): "최대한 짧게, 모든 내용 포함"을 동시 요청.
- 증상: 둘 다 충족 못 함.
- 원인: 제약 상충.
- 확인 방법: 우선순위 확인.
- 예방 규칙: 제약의 우선순위를 정한다.

#### C-060 · 예시 없는 모호한 톤
- 상황(가상): "딱딱하지 않게"라고만 요청.
- 증상: 톤이 매번 달라짐.
- 원인: 톤 기준 미제시.
- 확인 방법: 참조 문체와 비교.
- 예방 규칙: 참조 예시 문장을 함께 준다.

#### C-061 · 부정 지시만 사용
- 상황(가상): "길게 쓰지 마, 어렵게 쓰지 마"만 반복.
- 증상: 무엇을 원하는지 불명확한 결과.
- 원인: 대안·기준 부재.
- 확인 방법: 원하는 모습이 나왔는지 확인.
- 예방 규칙: 하지 말 것 + 해야 할 것을 함께 준다.

#### C-062 · 컨텍스트 초과 문서 통째 투입
- 상황(가상): 긴 문서를 한 번에 붙여 요약 요청.
- 증상: 뒤쪽 내용 누락.
- 원인: 컨텍스트 창 초과.
- 확인 방법: 문서 끝부분 내용 반영 여부 확인.
- 예방 규칙: 구간을 나눠 처리하고 요약 로그를 남긴다.

#### C-063 · 언어·지역 미지정
- 상황(가상): 특정 국가 대상 문서를 요청.
- 증상: 다른 지역 기준 표현 혼입.
- 원인: 언어·지역 미지정.
- 확인 방법: 대상 지역 표현 확인.
- 예방 규칙: 언어·지역을 명시한다.

#### C-064 · 완료 기준 없음
- 상황(가상): "적당히 정리해줘"라고 요청.
- 증상: 끝난 시점을 알 수 없음.
- 원인: 완료 정의 부재.
- 확인 방법: 완료 여부 판정 가능성 확인.
- 예방 규칙: "무엇이 되면 끝"인지 먼저 적는다.

#### C-065 · 반복 지시로 조건 변경
- 상황(가상): 같은 요청에서 조건을 조금씩 바꿈.
- 증상: 서로 다른 결과가 섞임.
- 원인: 지시 이력 혼선.
- 확인 방법: 최종 조건 반영 확인.
- 예방 규칙: 조건을 한곳에 고정하고 변경 시 명시한다.

#### C-066 · 권한 범위 미지정(무엇을 고쳐도 되는지)
- 상황(가상): 파일 수정을 맡기며 범위를 안 정함.
- 증상: 건드리면 안 되는 파일까지 수정.
- 원인: 권한 한계 미명시.
- 확인 방법: 변경 파일 목록 확인.
- 예방 규칙: 고쳐도 되는 대상과 금지를 명시한다.
